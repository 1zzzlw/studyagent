# 第 2 章：客户端创建方式

## 本章目标

掌握 Chroma 的主要 Client 创建方式，并知道每一种方式的数据存放位置、生命周期和适用场景。每种方式都完成一次相同的最小闭环：

1. 创建 Client；
2. 创建或获取 Collection；
3. 插入一批数据；
4. 查询一次并观察结果。

本章示例使用手写的二维向量，不调用真实 Embedding 模型。这样可以先把注意力放在 Client 的差异上，也能避免首次运行时下载默认模型。二维向量只用于教学，不能代表真实文本的语义。

## 1. EphemeralClient：内存模式

~~~python
import chromadb

client = chromadb.EphemeralClient()
~~~

特点：

- 数据只存在于当前进程；
- 程序退出后不保证保留；
- 适合 Notebook、单元测试和临时实验；
- 不需要单独启动 Chroma Server。

### 最小使用示例

下面这一个单元格完成创建、插入和查询：

~~~python
import chromadb

client = chromadb.EphemeralClient()
collection = client.get_or_create_collection("ephemeral-client-demo")

collection.add(
    ids=["chroma-1", "python-1"],
    documents=["Chroma 是一个向量数据库", "Python 是一种编程语言"],
    embeddings=[[1.0, 0.0], [0.0, 1.0]],
)

result = collection.query(
    query_embeddings=[[0.9, 0.1]],
    n_results=1,
)

print(result["ids"][0])
print(result["documents"][0])
print(result["distances"][0])
~~~

重点观察：

- `query()` 的结果按“查询批次”分组，所以这里要先取 `[0]`；
- 查询向量更接近 `[1.0, 0.0]`，因此预期返回 `chroma-1`；
- 重启 Kernel 后重新创建 `EphemeralClient`，原数据不会保留。

部分入门示例会使用 `chromadb.Client()` 创建进程内客户端。当前学习优先使用语义更明确的 `EphemeralClient`，因为看到名称就能判断数据不会持久化。

## 2. PersistentClient：本地持久化模式

~~~python
client = chromadb.PersistentClient(path="./storage/chroma")
~~~

特点：

- 数据自动写入指定目录；
- 下次使用相同目录仍能读取；
- 适合本地开发和小型单机实验；
- 官方建议生产场景优先考虑服务端模式。

相对路径基于当前工作目录解析。为了避免从不同目录启动时连接到不同数据库，练习时也应观察 path.resolve()。

### 最小使用示例

~~~python
from pathlib import Path

import chromadb

db_path = Path("./storage/chroma-persistent-demo").resolve()
print("数据库目录：", db_path)

client = chromadb.PersistentClient(path=str(db_path))
collection = client.get_or_create_collection("persistent-client-demo")

collection.add(
    ids=["chroma-1", "python-1"],
    documents=["Chroma 是一个向量数据库", "Python 是一种编程语言"],
    embeddings=[[1.0, 0.0], [0.0, 1.0]],
)

result = collection.query(
    query_embeddings=[[0.9, 0.1]],
    n_results=1,
)

print(result["ids"][0])
print(result["documents"][0])
~~~

重点观察：

- 运行后 `db_path` 对应的目录会出现数据库文件；
- 重启 Kernel，再使用同一个 `path` 和集合名称，可以继续查询原数据；
- 如果从不同工作目录运行相同的相对路径，可能会创建两套数据库。

`add()` 适合学习“新增”。持久化示例重复运行时，已有 ID 不会被当成新记录再次插入；需要反复修改同一批数据时，后续可以改用 `upsert()`。

## 3. HttpClient：同步服务端模式

先启动服务：

~~~powershell
chroma run --path ./storage/chroma-server
~~~

再连接：

~~~python
client = chromadb.HttpClient(
    host="localhost",
    port=8000,
    ssl=False,
)
~~~

可选参数还包括 headers、tenant、database 和 Settings。

### 最小使用示例

必须先让上面的 Chroma Server 保持运行，再在 Notebook 中执行：

~~~python
import chromadb

client = chromadb.HttpClient(
    host="localhost",
    port=8000,
    ssl=False,
)
print("服务端心跳：", client.heartbeat())

collection = client.get_or_create_collection("http-client-demo")
collection.add(
    ids=["chroma-1", "python-1"],
    documents=["Chroma 是一个向量数据库", "Python 是一种编程语言"],
    embeddings=[[1.0, 0.0], [0.0, 1.0]],
)

result = collection.query(
    query_embeddings=[[0.9, 0.1]],
    n_results=1,
)

print(result["ids"][0])
print(result["documents"][0])
~~~

重点观察：

- `heartbeat()` 成功说明 Notebook 已经连到服务端；
- 数据由 Chroma Server 管理，不在 Notebook 进程内；
- 关闭 Notebook 不会自动删除服务端数据；
- 若出现连接拒绝，先确认服务是否启动、端口是否为 `8000`，再检查 `host`。

## 4. AsyncHttpClient：异步服务端模式

~~~python
import chromadb

async def main():
    client = await chromadb.AsyncHttpClient(
        host="localhost",
        port=8000,
        ssl=False,
    )
    collection = await client.get_or_create_collection("async-demo")
~~~

异步 Client 的方法也需要 await。它适合 FastAPI 等异步服务，但不等于查询一定更快；主要价值是等待网络 I/O 时不阻塞事件循环。

### Notebook 最小使用示例

Jupyter 支持顶层 `await`，因此不需要在 Notebook 里调用 `asyncio.run()`。同样需要先启动 Chroma Server：

~~~python
import chromadb

client = await chromadb.AsyncHttpClient(
    host="localhost",
    port=8000,
    ssl=False,
)
print("服务端心跳：", await client.heartbeat())

collection = await client.get_or_create_collection("async-http-client-demo")
await collection.add(
    ids=["chroma-1", "python-1"],
    documents=["Chroma 是一个向量数据库", "Python 是一种编程语言"],
    embeddings=[[1.0, 0.0], [0.0, 1.0]],
)

result = await collection.query(
    query_embeddings=[[0.9, 0.1]],
    n_results=1,
)

print(result["ids"][0])
print(result["documents"][0])
~~~

重点观察：

- 创建 Client、获取 Collection、插入和查询都需要 `await`；
- 数据位置和 `HttpClient` 相同，都在服务端；
- Notebook 中不要再套一层 `asyncio.run()`，否则可能遇到“事件循环已经在运行”的错误。

## 5. CloudClient：Chroma Cloud

~~~python
client = chromadb.CloudClient(
    tenant="your-tenant",
    database="your-database",
    api_key="your-api-key",
)
~~~

也可以使用环境变量：

~~~dotenv
CHROMA_TENANT=your-tenant
CHROMA_DATABASE=your-database
CHROMA_API_KEY=your-api-key
~~~

API Key 不应写入 Notebook 或提交到 Git。

### 最小使用示例

运行前需要准备 Chroma Cloud 账号、Tenant、Database 和 API Key。下面从环境变量读取凭证：

~~~python
import os

import chromadb
from dotenv import load_dotenv

load_dotenv()

client = chromadb.CloudClient(
    tenant=os.environ["CHROMA_TENANT"],
    database=os.environ["CHROMA_DATABASE"],
    api_key=os.environ["CHROMA_API_KEY"],
)

collection = client.get_or_create_collection("cloud-client-demo")
collection.add(
    ids=["chroma-1", "python-1"],
    documents=["Chroma 是一个向量数据库", "Python 是一种编程语言"],
    embeddings=[[1.0, 0.0], [0.0, 1.0]],
)

result = collection.query(
    query_embeddings=[[0.9, 0.1]],
    n_results=1,
)

print(result["ids"][0])
print(result["documents"][0])
~~~

重点观察：

- 数据写入指定的 Cloud Tenant 和 Database；
- 重启 Notebook 后仍能重新连接并查询；
- `KeyError: 'CHROMA_API_KEY'` 表示环境变量没有加载成功，不是 Chroma 查询问题；
- 不要打印 API Key，也不要把 `.env` 提交到 Git。

## 6. 怎样选择

| 场景 | 推荐 Client |
| --- | --- |
| 临时实验、单元测试 | EphemeralClient |
| 本地持久化学习 | PersistentClient |
| 独立 Chroma 服务 | HttpClient |
| 异步 Python 服务 | AsyncHttpClient |
| 托管服务 | CloudClient |

## 7. Client 通用操作

~~~python
client.heartbeat()
client.get_version()
client.list_collections()
client.count_collections()
~~~

reset 会删除当前数据库中的全部 Collection 和数据，且不可恢复。不要把它当成普通清理方法。

## 8. Notebook 分单元格练习

不要一次复制本章所有示例。建议每种 Client 分成以下单元格：

1. **Cell 1：创建 Client**——打印 Client 类型；服务端模式额外调用 `heartbeat()`。
2. **Cell 2：创建 Collection**——打印集合名称和 `collection.count()`。
3. **Cell 3：插入数据**——只执行一次 `add()`，再次打印数量。
4. **Cell 4：执行查询**——分别打印 `ids`、`documents` 和 `distances`。
5. **Cell 5：生命周期实验**——重启 Kernel 或重启服务，再次连接和查询。
6. **Cell 6：Markdown 总结**——记录数据到底保存在 Notebook、磁盘、服务端还是 Cloud。

建议按以下顺序练习：

1. 先完成 `EphemeralClient`，理解最短链路；
2. 再完成 `PersistentClient`，观察本地文件和 Kernel 重启后的变化；
3. 启动 Chroma Server，分别完成同步和异步客户端；
4. 只有拥有 Chroma Cloud 凭证时才运行 `CloudClient`。
