# 第 6 章：查询与召回

## 本章目标

只观察 Retriever，不调用聊天模型。这样可以把“没找到资料”和“模型没用好资料”彻底分开。

## 1. 执行一次查询

先确保完成 `sync`，然后运行：

```powershell
uv run python 06-embedding-basics\run.py query "玻璃幕墙应该怎样挂接到墙体？" --k 3
```

查询流程：

```text
问题文本
  → embed_query()
  → 一个问题向量
  → collection.query(query_embeddings=[...])
  → cosine 距离排序
  → Top 3 原文和 metadata
```

每次查询只向量化当前问题，不会重新向量化知识文档。

## 2. 如何阅读输出

每个结果会显示：

- `distance`：当前使用 cosine 距离，通常越小越接近；
- `source`：真实来源文件；
- `heading`：原文标题路径；
- `chunk_id`：后续追踪和引用用的唯一 ID；
- 文本块原文。

不要一开始就设置一个想当然的固定阈值。先准备正例和反例，观察当前模型与当前知识库的真实距离分布，再决定阈值。

## 3. metadata 过滤

本教程查询条件是：

```python
where={
    "$and": [
        {"namespace": "embedding_basics"},
        {"doc_scope": "generation"},
    ]
}
```

作用是：

- 不误查同一集合中的其他逻辑数据；
- 排除 `README.md` 这类目录索引文档。

WildAgent 还会按 `doc_type`、`entity_type` 等业务 metadata 过滤。例如查询屋顶规则时，优先限定屋顶组件文档，减少别的建筑知识造成噪声。

## 4. Top-K 的取舍

- K 太小：正确块可能排在下一名，被漏掉；
- K 太大：无关块增多，浪费 Prompt 上下文并干扰聊天模型。

Top-K 不是越大越安全。应通过带标准来源的测试问题测量 Recall@K，再结合上下文预算选择。

## 5. 检索后怎样进入聊天模型

本模块故意停在 Retriever，因为你已经在 `02-rag` 学过 Prompt 与聊天模型。完整 RAG 只需把结果格式化：

```text
[来源 1 | source=... | heading=...]
召回原文

[来源 2 | source=... | heading=...]
召回原文
```

再把它放入 System Prompt 或当前 Agent 节点的任务 Prompt。

正确的调试顺序是：

```text
Top-K 有正确块吗？
  → 有：再检查 Prompt 是否包含它
  → 有：再检查聊天模型是否遵循它
```
