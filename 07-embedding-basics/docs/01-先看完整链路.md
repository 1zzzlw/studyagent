# 第 1 章：先看完整链路

## 本章目标

先建立一张不会混乱的地图。学完本章，你应该能区分“建库阶段”和“查询阶段”，并知道服务启动不等于每次都重建索引。

## 1. 两条数据流

建库阶段处理知识文档：

```text
Markdown 文件
  → 扫描文件
  → 切成文本块 Chunk
  → 每个 Chunk 调用 Embedding
  → 得到向量
  → 把 id + 原文 + metadata + 向量写进 Chroma
```

查询阶段处理用户问题：

```text
用户问题
  → 调用同一个 Embedding 模型
  → 得到问题向量
  → Chroma 比较问题向量和文档向量
  → 返回距离最近的 Top-K 文本块
  → 业务程序把文本块放进 Prompt
  → 聊天模型生成回答或建筑方案
```

Embedding 模型不负责回答问题。它只负责把文本映射到一个可比较的数字空间。

## 2. 向量库保存了什么

本教程为每个文本块保存四类信息：

| 字段 | 用途 |
|---|---|
| `id` | 唯一标识文本块，用于更新和删除 |
| `document` | 原始文本，召回后要交给人或聊天模型阅读 |
| `metadata` | 来源、标题、用途等，用于追踪和过滤 |
| `embedding` | 浮点数向量，用于相似度计算 |

只保存向量而不保存原文没有实用价值，因为聊天模型最终需要读到可理解的文本。

## 3. “初始化”“启动”“调用”分别指什么

### 初始化

创建 Chroma 客户端和集合。集合不存在时创建，存在时复用。初始化本身不代表已经有数据。

### 首次建库

扫描全部文档、切块、调用 Embedding，并写入 Chroma。这通常是最慢、最可能产生接口费用的一步。

### 服务启动

重新打开磁盘上的 Chroma 集合。已有索引可以立即读取；如果启用自动同步，再在后台比较知识文档是否变化。

### 查询调用

只把当前问题向量化一次，然后从已有文档向量中选 Top-K。正常情况下不会在每个用户问题到来时重新向量化全部知识库。
