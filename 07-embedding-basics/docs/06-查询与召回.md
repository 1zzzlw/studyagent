# 第 6 章：查询与召回

## 本章目标

只观察 Retriever，不调用聊天模型。这样可以把“没找到资料”和“模型没用好资料”彻底分开。

## 1. 执行一次查询

先确保完成 `sync`，然后运行：

```powershell
uv run python 07-embedding-basics\run.py query "玻璃幕墙应该怎样挂接到墙体？" --k 3
```

查询流程：

```text
问题文本
  → embed_query()
  → 一个问题向量
  → collection.query(query_embeddings=[...])
  → cosine 距离排序
  → Top 3 原文和 metadata
```

每次查询只向量化当前问题，不会重新向量化知识文档。

## 2. 如何阅读输出

每个结果会显示：

- `distance`：当前使用 cosine 距离，通常越小越接近；
- `source`：真实来源文件；
- `heading`：原文标题路径；
- `chunk_id`：后续追踪和引用用的唯一 ID；
- 文本块原文。

不要一开始就设置一个想当然的固定阈值。先准备正例和反例，观察当前模型与当前知识库的真实距离分布，再决定阈值。

## 3. metadata 过滤

本教程查询条件是：

```python
where={
    "$and": [
        {"namespace": "embedding_basics"},
        {"doc_scope": "generation"},
    ]
}
```

作用是：

- 不误查同一集合中的其他逻辑数据；
- 排除 `README.md` 这类目录索引文档。

WildAgent 还会按 `doc_type`、`entity_type` 等业务 metadata 过滤。例如查询屋顶规则时，优先限定屋顶组件文档，减少别的建筑知识造成噪声。

## 4. Top-K 的取舍

- K 太小：正确块可能排在下一名，被漏掉；
- K 太大：无关块增多，浪费 Prompt 上下文并干扰聊天模型。

Top-K 不是越大越安全。应通过带标准来源的测试问题测量 Recall@K，再结合上下文预算选择。

## 5. 检索后怎样进入聊天模型

本模块故意停在 Retriever，因为你已经在 `02-rag` 学过 Prompt 与聊天模型。完整 RAG 只需把结果格式化：

```text
[来源 1 | source=... | heading=...]
召回原文

[来源 2 | source=... | heading=...]
召回原文
```

再把它放入 System Prompt 或当前 Agent 节点的任务 Prompt。

正确的调试顺序是：

```text
Top-K 有正确块吗？
  → 有：再检查 Prompt 是否包含它
  → 有：再检查聊天模型是否遵循它
```

## 6. Notebook 分单元格练习：离线验证查询与过滤

### Cell 1：定义关键词假 Embedding

依赖：公共初始化 Cell。

```python
from pathlib import Path
import tempfile

from embedding_lab.chunking import Chunk
from embedding_lab.vector_store import ChromaVectorStore


class KeywordEmbeddings:
    def _vector(self, text: str) -> list[float]:
        if "幕墙" in text:
            return [1.0, 0.0]
        if "楼梯" in text:
            return [0.0, 1.0]
        return [0.5, 0.5]

    def embed_documents(self, texts: list[str]) -> list[list[float]]:
        return [self._vector(text) for text in texts]

    def embed_query(self, text: str) -> list[float]:
        return self._vector(text)
```

### Cell 2：准备带 metadata 的 Chunk

依赖：Cell 1。

```python
def make_chunk(
    chunk_id: str,
    text: str,
    source: str,
    doc_scope: str,
) -> Chunk:
    return Chunk(
        id=chunk_id,
        text=text,
        metadata={
            "namespace": "query_test",
            "source": source,
            "heading": source,
            "doc_scope": doc_scope,
        },
    )


chunks = [
    make_chunk(
        "wall-001",
        "幕墙需要通过 parentWall 挂接",
        "components/walls.md",
        "generation",
    ),
    make_chunk(
        "stair-001",
        "楼梯连接上下楼层",
        "components/stairs.md",
        "generation",
    ),
    make_chunk(
        "readme-001",
        "幕墙和楼梯文档目录",
        "README.md",
        "index",
    ),
]
```

### Cell 3：写入临时 Chroma

依赖：Cell 1、Cell 2。

```python
persist_dir = Path(tempfile.mkdtemp(prefix="studyagent-query-"))
store = ChromaVectorStore(
    persist_dir=persist_dir,
    collection_name="query_demo",
    namespace="query_test",
    index_signature="keyword-model-v1",
)
embeddings = KeywordEmbeddings()

store.sync(chunks, embeddings)
print("索引状态：", store.status())
```

### Cell 4：查询并验证过滤结果

依赖：Cell 3。

```python
hits = store.query("幕墙应该怎样挂接？", embeddings, k=3)

assert hits
assert hits[0].id == "wall-001"
assert all(hit.metadata["doc_scope"] == "generation" for hit in hits)
assert all(hit.id != "readme-001" for hit in hits)

for rank, hit in enumerate(hits, start=1):
    print(f"Top {rank} | distance={hit.distance}")
    print("source:", hit.metadata["source"])
    print("text:", hit.text)
```

这个测试分别证明：

- 查询文本只调用一次 `embed_query()`；
- `query_embeddings` 必须套在列表中，因为 Chroma 查询接口支持批量问题；
- `namespace` 与 `doc_scope` 过滤在向量排序前限制候选记录；
- 即使 README 文本包含“幕墙”，也会因为 `doc_scope=index` 被排除；
- `distance` 是距离，当前 cosine 配置下通常越小越相似。

### Cell 5：Top-K 对比实验

依赖：Cell 3。把 `k` 依次改成 `1`、`2`、`10`：

```python
for k in (1, 2, 10):
    current_hits = store.query("幕墙应该怎样挂接？", embeddings, k=k)
    print(f"k={k}, 返回数量={len(current_hits)}")
    print([hit.id for hit in current_hits])
```

记录：

```text
返回数量、第一名来源、最后一名距离、是否出现无关结果
```

不要只凭一次查询设置距离阈值。至少再准备一个同义改写问题和一个知识库没有答案的问题，比较三类距离分布。

### Cell 6：主动制造维度错误

依赖：Cell 3。旧集合使用二维向量，临时改用一个返回三维问题向量的对象：

```python
class WrongDimensionEmbeddings(KeywordEmbeddings):
    def embed_query(self, text: str) -> list[float]:
        return [1.0, 0.0, 0.0]


try:
    store.query(
        "幕墙应该怎样挂接？",
        WrongDimensionEmbeddings(),
        k=1,
    )
except Exception as exc:
    print("预期维度错误：", type(exc).__name__, exc)
else:
    raise AssertionError("三维问题向量不应该查询二维集合")
```

错误发生在 Chroma 比较向量之前，说明建库模型与查询模型不一致；修改 Top-K 或 Prompt 不能解决它。
