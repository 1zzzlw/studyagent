# 第 8 章：排错、验证与练习

## 本章目标

形成稳定的排错顺序，不把所有问题都归因于 Prompt 或聊天模型。

## 1. 排错顺序

```text
知识文档里有答案吗？
  ↓
扫描到该文件了吗？
  ↓
切块后答案还完整吗？
  ↓
该块成功写入 Chroma 了吗？
  ↓
问题与文档使用同一个 Embedding 模型吗？
  ↓
正确块进入 Top-K 了吗？
  ↓
召回块确实进入 Prompt 了吗？
  ↓
聊天模型是否依据证据输出？
```

前六步都属于检索系统。只有最后两步才开始涉及生成模型。

## 2. 常见现象

| 现象 | 优先检查 |
|---|---|
| 提示缺少 `EMBEDDING_BASE_URL` 或 `EMBEDDING_API_KEY` | `.env` 是否仍只配置了旧的 `LLM_*` 变量 |
| 对话能调用、向量却返回 401/404 | 是否把聊天供应商的 URL 或 Key 错给了腾讯向量 Client |
| 服务端提示模型类型为 `Rerank` | `EMBEDDING_MODEL` 填成了重排序模型，改用真正的文本向量模型 |
| 腾讯 TokenHub 返回参数错误 | 文本接口是否使用 `/v1/embeddings`、文本向量模型和字符串输入 |
| `inspect` 扫描文档数为 0 | `knowledge_dir` 和文件后缀 |
| 切块把规则拆散 | Markdown 标题、`chunk_size`、`chunk_overlap` |
| 首次 `sync` 很慢 | 文本块数量、接口延迟、每批限制 |
| 第二次 `sync` 仍全量向量化 | chunk ID 是否稳定、参数是否变化 |
| 查询提示索引签名不同 | 模型、接口地址或切块参数改变 |
| Chroma 报向量维度不一致 | 建库和查询使用了不同模型 |
| Top-K 全是 README | metadata 是否标记和过滤 `doc_scope` |
| Top-K 有答案但最终回答错 | Prompt 组装与聊天模型遵循性 |
| `contents is neither str nor list of str` | 确认发送原始字符串，不要发送 token ID |

## 3. 本机环境异常与业务错误要分开

如果 Chroma 导入阶段出现 Windows `WinError 10106`，错误来自 Python 的 `asyncio/_overlapped` 初始化，不代表扫描、切块或检索业务逻辑失败。先在系统层修复 Winsock/运行环境，再重新做 Chroma 运行验证。

不要为了绕过系统异常去修改切块或查询代码。

## 4. 四组练习

### 练习 A：证明持久化

1. 执行 `sync`；
2. 关闭终端；
3. 新开终端执行 `status`；
4. 确认 count 不变且没有 Embedding 请求。

### 练习 B：证明增量同步

1. 连续执行两次 `sync`；
2. 第二次确认 `added=0`；
3. 新增一小节知识；
4. 再同步并观察新增数；
5. 恢复文档并再次同步，观察删除数。

### 练习 C：比较切块参数

分别尝试 `900/150` 与 `500/80`，先运行 `inspect` 比较块数量和完整性。若要做真实检索对比，必须使用独立 collection 或显式重建，不能拿旧向量混用。

### 练习 D：准备检索测试集

至少准备三类问题：

- 明确应该命中某个来源的正例；
- 同一含义但换一种说法的改写例；
- 知识库没有答案的反例。

记录 `expected_source`，然后统计正确来源是否进入 Top-K。只有这样才能把“看起来搜到了内容”升级为可重复的 Recall@K 验证。

## 5. 验收清单

完成本模块后，请独立演示：

- `inspect`：解释扫描数、块数、标题与来源；
- `probe`：在不读写 Chroma 的前提下证明向量配置和模型可用；
- `sync`：解释哪些步骤产生 Embedding 请求；
- `status`：证明索引持久化；
- 第二次 `sync`：证明未变化块不会重新向量化；
- `query`：解释问题向量、cosine 距离与 Top-K；
- 回到 WildAgent：指出后台同步和 Agent 节点调用位置。

能完成这些演示，就已经掌握从向量初始化到生产调用的完整基础链路。

## 6. Notebook 分单元格练习：主动触发四层错误

在 `01.basic.ipynb` 中建立 `# 第 8 章：排错实验`。目标不是“所有 Cell 都没有异常”，而是确认每个失败都发生在预期层级并被正确捕获。

### Cell 1：导入并定义错误捕获工具

依赖：公共初始化 Cell。

```python
from pathlib import Path
import tempfile

from embedding_lab.chunking import Chunk, MarkdownChunker
from embedding_lab.documents import collect_markdown_paths
from embedding_lab.vector_store import ChromaVectorStore


def expect_error(label: str, expected_type: type[Exception], action) -> None:
    try:
        action()
    except expected_type as exc:
        print(f"[符合预期] {label}: {type(exc).__name__}: {exc}")
    else:
        raise AssertionError(f"{label} 没有触发 {expected_type.__name__}")
```

### Cell 2：触发扫描层和切块层错误

### Cell 4：准备一个可写入的二维假模型

依赖：Cell 1。

```python
class FixedEmbeddings:
    def embed_documents(self, texts: list[str]) -> list[list[float]]:
        return [[1.0, 0.0] for _ in texts]

    def embed_query(self, text: str) -> list[float]:
        return [1.0, 0.0]
```

### Cell 5：触发索引签名错误

依赖：Cell 4。

```python
# 第四层：同一集合被另一套索引签名打开。

                "source": "walls.md",
                "heading": "幕墙",
                "doc_scope": "generation",
            },
        )

store_v2 = ChromaVectorStore(
    persist_dir=signature_dir,
    collection_name="signature_demo",
    namespace="failure_test",
    index_signature="model-b-chunk-v1",

expect_error(
    "索引签名不一致",
    RuntimeError,
    store_v2.status,
```

### 怎样解读结果

| 错误 | 所在层级 | 不应该先改什么 |
|---|---|---|
| 目录不存在 | 文档扫描 | Embedding 参数 |
| 切块参数非法 | Chunker | Chroma 集合 |
| 集合不存在 | 向量库状态 | Prompt |
| 索引签名不同 | 模型/切块协议 | Top-K |

如果脚本在导入 Chroma 时直接出现 `WinError 10106`，说明没有执行到第三、第四个业务实验。此时应记录为运行环境阻塞，不能说“签名测试失败”。
