# 第 10 章：腾讯向量服务与配置解耦

## 本章目标

完成下面这条配置边界：

```text
聊天请求
→ LLM_MODEL + LLM_BASE_URL + LLM_API_KEY
→ chat_client.chat.completions.create(...)

文档/问题向量化
→ EMBEDDING_MODEL + EMBEDDING_BASE_URL + EMBEDDING_API_KEY
→ embedding_client.embeddings.create(...)
```

二者使用同一个 `openai.OpenAI` SDK 类型，不代表必须使用同一个 Client、供应商、地址或密钥。

## 1. 为什么三个向量变量都要拆开

只增加 `EMBEDDING_BASE_URL` 还不够。腾讯 TokenHub 的模型名、接口地址和 API Key 都属于向量服务，应该作为一个不可拆散的配置组：

| 配置 | 所属能力 | 是否进入索引签名 |
|---|---|---|
| `EMBEDDING_MODEL` | 决定向量空间和维度 | 是 |
| `EMBEDDING_BASE_URL` | 决定请求发往哪个服务 | 是 |
| `EMBEDDING_API_KEY` | 只负责该服务鉴权 | 否，绝不能写入索引 |

聊天变量只服务聊天模型。若 Embedding 悄悄回退到 `LLM_*`，即使对话测试成功，也不能证明 `/embeddings` 可用，而且很容易把请求发给错误供应商。

## 2. 腾讯 TokenHub 当前文本向量接口

腾讯云官方文档说明，TokenHub 文本向量接口兼容 OpenAI Embeddings API：

- Base URL：`https://tokenhub.tencentmaas.com/v1`
- 完整端点：`POST /v1/embeddings`
- `kinfra-text-embedding-0.6b`：固定 1024 维
- `kinfra-text-embedding-4b`：固定 2560 维
- `input` 支持字符串或字符串数组
- `encoding_format` 只支持 `float`

参考：[腾讯云 TokenHub 向量模型官方文档](https://cloud.tencent.com/document/product/1823/133515)。

本学习模块继续把单批限制在 10 条。这比腾讯文档给出的建议上限更保守，也便于观察每一批请求。

## 3. `.env` 配置

将真实值写在项目根目录 `.env`，不要写进 Notebook：

```dotenv
# 原有聊天服务，不需要因为更换向量模型而改变
LLM_MODEL=你的聊天模型
LLM_BASE_URL=https://你的聊天供应商/v1
LLM_API_KEY=你的聊天密钥

# 腾讯云 TokenHub 文本向量服务
EMBEDDING_MODEL=kinfra-text-embedding-0.6b
EMBEDDING_BASE_URL=https://tokenhub.tencentmaas.com/v1
EMBEDDING_API_KEY=你的_TokenHub_API_Key
```

若你选择 4B 模型，只修改 `EMBEDDING_MODEL`：

```dotenv
EMBEDDING_MODEL=kinfra-text-embedding-4b
```

不要在同一个旧 Chroma collection 中混用 1024 维和 2560 维向量。

### Cell 2：证明两个 Client 配置互不污染

依赖：Cell 1。此 Cell 只创建对象，不发送网络请求。

```python
from openai import OpenAI

chat_client = OpenAI(
    api_key=os.environ["LLM_API_KEY"],
    base_url=os.environ["LLM_BASE_URL"],
    timeout=60.0,
    max_retries=1,
)

embedding_client = OpenAI(
    api_key=os.environ["EMBEDDING_API_KEY"],
    base_url=os.environ["EMBEDDING_BASE_URL"],
    timeout=60.0,
    max_retries=1,
)

print("两个对象类型相同：", type(chat_client) is type(embedding_client))
print("两个对象不是同一个实例：", chat_client is not embedding_client)
print("聊天地址：", chat_client.base_url)
print("向量地址：", embedding_client.base_url)
```

你应该看到：类型相同、实例不同、Base URL 各自独立。

### Cell 3：只调用一次腾讯 Embedding

依赖：Cell 2。此 Cell 会产生一次真实请求和少量费用。

```python
response = embedding_client.embeddings.create(
    model=os.environ["EMBEDDING_MODEL"],
    input=[
        "Chroma 用于保存和查询向量",
        "Rerank 用于对召回候选重新排序",
    ],
    encoding_format="float",
)

items = sorted(response.data, key=lambda item: item.index)
vectors = [list(item.embedding) for item in items]

print("返回数量：", len(vectors))
print("第一个向量维度：", len(vectors[0]))
print("第二个向量维度：", len(vectors[1]))
print("前 5 维：", vectors[0][:5])

assert len(vectors) == 2
assert len(vectors[0]) == len(vectors[1])
```

选择 `0.6b` 时维度应为 1024；选择 `4b` 时应为 2560。不要打印完整向量。

### Cell 4：通过项目适配器调用同一服务

依赖：Cell 1。此 Cell会再次产生一次真实请求。

```python
from embedding_lab.config import Settings
from embedding_lab.embeddings import OpenAICompatibleEmbeddings

settings = Settings()
settings.require_embedding_config()

embeddings = OpenAICompatibleEmbeddings(
    model=settings.embedding_model,
    base_url=settings.embedding_base_url,
    api_key=settings.embedding_api_key,
    batch_size=10,
    timeout=60.0,
)

query_vector = embeddings.embed_query("玻璃幕墙怎样与主体墙连接？")

print("Settings 模型：", settings.embedding_model)
print("Settings 地址：", settings.embedding_base_url)
print("问题向量维度：", len(query_vector))
```

这一 Cell 证明 `Settings → OpenAICompatibleEmbeddings → client.embeddings.create()` 的真实调用链已经全部使用 `EMBEDDING_*`。

### Cell 5：离线观察索引签名

依赖：Cell 4。此 Cell 不联网。

```python
current_signature = settings.index_signature()

other_model_settings = Settings(
    embedding_model="kinfra-text-embedding-4b",
    embedding_base_url=settings.embedding_base_url,
    embedding_api_key=settings.embedding_api_key,
)

print("当前签名：", current_signature)
print("更换模型后的签名：", other_model_settings.index_signature())
print("签名是否变化：", current_signature != other_model_settings.index_signature())
```

API Key 不进入签名；更换 Key 不会改变向量空间。模型或 Base URL 改变时签名会变化，程序会阻止误用旧集合。

## 5. 参考实现的安全执行顺序

在项目根目录执行：

```powershell
# 1. 只验证腾讯模型、地址、Key 和返回维度，不碰 Chroma
uv run python 07-embedding-basics\run.py probe

# 2. 查看旧索引状态，不调用模型
uv run python 07-embedding-basics\run.py status

# 3. 确认接受重建后，再重建本教学集合
uv run python 07-embedding-basics\run.py sync --rebuild

# 4. 用相同腾讯模型生成问题向量并查询
uv run python 07-embedding-basics\run.py query "玻璃幕墙应该怎样挂接到墙体？" --k 3
```

`probe` 成功只说明模型接口可用，不说明旧索引兼容，也不说明检索质量合格。重建后仍要用代表性问题检查 Top-K。

## 7. 故障定位表

| 现象 | 根因方向 | 处理 |
|---|---|---|
| `401` / `AuthenticationError` | TokenHub Key 缺失、错误或无权限 | 检查 `EMBEDDING_API_KEY`，不要拿聊天 Key 代替 |
| `404` | Base URL 或服务端点错误 | Base URL 填到 `/v1`，SDK 会追加 `/embeddings` |
| 返回 `processor type Rerank` | 模型是重排序模型，不是向量模型 | 改用文本 Embedding 模型 |
| 返回维度与旧集合不一致 | 已更换模型或服务 | 使用新集合或 `sync --rebuild` |
| 聊天正常、Embedding 失败 | 两套 Provider 独立，聊天成功不能证明向量配置正确 | 单独运行 `probe` |
| 探针成功但 Top-K 很差 | 接口可用但检索效果不合格 | 检查切片，并用标准问题集评测 |
