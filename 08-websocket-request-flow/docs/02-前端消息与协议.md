## 1. 前端发送链路

当前 WildAgent 前端的主链是：

```text
agentBridge.sendUserMessage(message)
→ 检查 WebSocket.OPEN
→ 收集 scene / selection / recent_messages / mode
→ protocol.createUserMessageRequest(...)
→ 生成 request_id
→ agentStore.startTurn(...)
→ ws.send(JSON.stringify(request))
```

源码位置：

- [`protocol.ts`](../../../WildAgent/wild-web/src/agent/protocol.ts)：协议版本和请求构造；
- [`agent.ts`](../../../WildAgent/wild-web/src/types/agent.ts)：请求与响应类型；
- [`agentBridge.ts`](../../../WildAgent/wild-web/src/agent/agentBridge.ts)：连接、发送和接收；
- Agent Store：把事件更新为界面可消费的状态。

## 2. user_message 的关键字段

| 字段 | 含义 | 初次跟链是否重点 |
|---|---|---|
| `protocol_version` | 前后端协议版本 | 是 |
| `type` | 消息分支，当前为 `user_message` | 是 |
| `request_id` | 一次请求/轮次的关联键 | 是 |
| `session_id` | 多轮会话关联键 | 是 |
| `message` | 用户文本 | 是 |
| `scene_id`、`scene_revision` | 当前场景及版本 | 先知道即可 |
| `scene_summary`、`blueprint` | 场景上下文 | 先知道即可 |
| `selection` | 当前选中的构件 ID | 修改意图时重要 |
| `thinking_mode` | 是否请求思考内容 | 后续11模块深入 |
| `plan_mode` | 是否进入计划审核路径 | 先关闭，减少分支 |
| `recent_messages` | 最近对话，用于意图消歧 | 先知道即可 |

第一次练习建议使用 `thinking_mode=False`、`plan_mode=False`，并提出知识问答，让 Graph 走最短路径。

## 3. 后端不会原样信任所有字段

后端 `_prepare_server_request()` 会复制请求，再补充或收敛服务端字段，例如：

- 把 `plan_mode` 收敛为严格布尔值；
- 使用服务端访问上下文覆盖前端自报身份；
- 根据配置对消息和最近对话做 PII 脱敏；
- 限制最近消息的角色、数量和长度；
- 生成安全检查结果。

因此“WebSocket 收到的原始 dict”和“写入任务的 prepared dict”也不是完全相同的对象。

## 4. 返回消息不是 LangGraph 原始事件

前端 `onmessage` 先做：

```text
JSON.parse(event.data)
→ 检查 protocol_version
→ 单独处理 pong / network_error
→ 用 event_seq 去重持久化事件
→ handleMessage(message)
→ switch(message.type)
→ 更新 Agent Store
```

`agent_step`、`thinking_delta`、`agent_reply`、`blueprint_generated` 是 WebSocket 业务协议；`on_chain_start`、`on_chain_end` 才是 LangGraph 内部事件。不要把两套名称混在一起。

### Cell 3：编写协议入口校验

- 依赖：Cell 1；

```python
KNOWN_CLIENT_MESSAGE_TYPES = {
    "ping",
    "presence_identify",
    "user_message",
    "resume_generation",
    "floor_plan_review",
    "style_review",
    "execution_plan_review",
    "execution_feedback",
}


def validate_client_message(data: dict) -> str:
    version = data.get("protocol_version")
    if version not in (None, AGENT_PROTOCOL_VERSION):
        raise ValueError(f"unsupported protocol version: {version}")

    message_type = data.get("type")
    if message_type not in KNOWN_CLIENT_MESSAGE_TYPES:
        raise ValueError(f"unknown message type: {message_type}")

    if message_type == "user_message":
        for field in ("request_id", "session_id", "message"):
            if not str(data.get(field) or "").strip():
                raise ValueError(f"missing field: {field}")

    return str(message_type)


print(validate_client_message(message_request))
```

## 6. 常见问题

### 为什么 `protocol_version` 可以为 None

当前后端兼容没有版本字段的旧客户端，但明确不接受一个不同的版本号。学习时仍应始终发送当前协议版本。

### 为什么不能直接在前端决定用户身份

前端数据可以被修改，服务端会根据连接头部生成访问上下文并覆盖相关字段。客户端请求是输入，不是可信事实。
