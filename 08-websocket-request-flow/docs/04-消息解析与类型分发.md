# 第04章：消息解析与类型分发

## 本章目标

读懂 `agent_websocket()` 在 `json.loads()` 之后怎样检查协议版本，再根据 `type` 把消息交给不同服务。

- 字典的 `get()`；

- 第02章的 JSON 序列化，第03章的接收循环。

## 1. 当前真实分发表

只读位置：[`ws_agent.py`](../../../WildAgent/wild-server/app/api/ws_agent.py) 的 `agent_websocket()` 接收循环。

| 客户端 `type` | 后端动作 | 是否进入 Graph |
| --- | --- | --- |
| `ping` | 返回 `pong` | 否 |
| `presence_identify` | 更新展示名 | 否 |
| `user_message` | 准备请求并 `start_job()` | 可能进入 |
| `resume_generation` | 附着任务并补发事件 | 不是新建运行 |
| `execution_plan_review` | 提交计划审核结果 | 可能恢复运行 |
| `execution_feedback` | 写入运行中反馈队列 | 否，供运行任务读取 |
| 其他或缺失 | 返回 `error` | 否 |

主循环的顺序非常重要：

```text
receive_text
→ heartbeat.touch
→ json.loads
→ protocol_version 校验
→ data.get("type")
→ 分支调用
```

JSON 错误或协议版本错误都会 `continue`，因此不会落入业务分支。

## 2. Notebook 分单元格观察

### Cell 1：写一个不执行业务的路由函数

- 输入：解析后的字典；
- 依赖：无；
- 预期：返回将要调用的动作名称；
- 观察：纯函数便于单元验证，不需要 WebSocket 或数据库。

```python
SUPPORTED_PROTOCOL = "1.0"

def route_client_message(data: dict) -> str:
    protocol_version = data.get("protocol_version")
    if protocol_version not in (None, SUPPORTED_PROTOCOL):
        return "reject_protocol"

    message_type = data.get("type")
    if message_type == "ping":
        return "send_pong"
    if message_type == "presence_identify":
        return "update_presence"
    if message_type == "user_message":
        return "start_job"
    if message_type == "resume_generation":
        return "resume_or_replay"
    if message_type == "execution_plan_review":
        return "submit_plan_review"
    if message_type == "execution_feedback":
        return "queue_feedback"
    return "reject_unknown_type"
```

代码解释：本函数只复刻“决策”，没有复刻服务调用。多个提前 `return` 让每个输入只产生一个动作。

### Cell 2：用 `unittest` 表格化验证所有分支

- 输入：消息与预期动作列表；
- 依赖：Cell 1；
- 预期：逐项打印且全部断言通过；
- 观察：缺失版本是兼容情况，错误版本优先于消息类型被拒绝。

```python
import unittest

route_cases = [
    ({"type": "ping", "protocol_version": "1.0"}, "send_pong"),
    ({"type": "presence_identify"}, "update_presence"),
    ({"type": "user_message"}, "start_job"),
    ({"type": "resume_generation"}, "resume_or_replay"),
    ({"type": "execution_plan_review"}, "submit_plan_review"),
    ({"type": "execution_feedback"}, "queue_feedback"),
    ({"type": "unknown"}, "reject_unknown_type"),
    ({"type": "ping", "protocol_version": "9.9"}, "reject_protocol"),
]

class RouteClientMessageTests(unittest.TestCase):
    def test_all_routes(self):
        for payload, expected in route_cases:
            with self.subTest(payload=payload):
                self.assertEqual(route_client_message(payload), expected)

suite = unittest.defaultTestLoader.loadTestsFromTestCase(RouteClientMessageTests)
result = unittest.TextTestRunner(verbosity=2).run(suite)
assert result.wasSuccessful()
```

代码解释：测试数据是二元组 `(输入, 预期)`；`subTest()` 会标出具体失败输入，而不是只告诉你整个循环失败。最后一项证明协议检查发生在 `type` 分发之前。

### Cell 3：观察 `dict.get()` 与下标访问的差别

- 输入：缺失 `type` 的空字典；
- 依赖：无；
- 预期：`get()` 返回 `None`，下标访问抛 `KeyError`；
- 观察：真实接收边界为什么大量使用 `get()`。

```python
empty_message = {}
print("get结果：", empty_message.get("type"))

try:
    print(empty_message["type"])
except KeyError as exc:
    print("下标访问失败：", type(exc).__name__, exc)
```

代码解释：外部输入不可信，字段可能缺失。`get()` 便于把缺失字段统一送入“未知类型”分支。

### Cell 4：模拟 `continue` 的作用

- 输入：一批包含错误版本和正确版本的消息；
- 依赖：Cell 1；
- 预期：只记录两个可执行动作；
- 观察：一条坏消息不会结束整个连接循环。

```python
batch = [
    {"type": "ping", "protocol_version": "9.9"},
    {"type": "ping", "protocol_version": "1.0"},
    {"type": "user_message", "protocol_version": "1.0"},
]

accepted_actions = []
for item in batch:
    action = route_client_message(item)
    if action.startswith("reject_"):
        print("跳过：", action)
        continue
    accepted_actions.append(action)

assert accepted_actions == ["send_pong", "start_job"]
accepted_actions
```

代码解释：`continue` 只跳过当前循环项，不等于 `return`，也不等于关闭 WebSocket。

### Cell 5：主动制造类型错误

- 输入：JSON 数组而不是 JSON 对象；
- 依赖：Cell 1；
- 预期：调用 `.get()` 时出现 `AttributeError`；
- 排查方向：成功解析 JSON 不代表顶层结构一定是对象。

```python
import json

wrong_shape = json.loads('[{"type": "ping"}]')
try:
    route_client_message(wrong_shape)
except AttributeError as exc:
    print(type(exc).__name__, str(exc))
```

代码解释：这是值得留意的边界情况。当前学习结论是“解析”和“结构验证”是两个阶段；是否要增强生产校验，应另开 WildAgent 修复任务并先补测试。
