## 1. 真实源码做了哪些准备

只读函数：[`_prepare_server_request()`](../../../WildAgent/wild-server/app/api/ws_agent.py)

| 动作 | 源码表达 | 目的 |
| --- | --- | --- |
| 浅复制请求 | `prepared = dict(data)` | 不直接覆盖接收到的原字典 |
| 严格转换计划模式 | `value is True` | 避免字符串 `"false"` 被当成真 |
| 覆盖访问身份 | `access.public_dict()` | 不信任前端自报身份 |
| 清洗主消息 | 转字符串、可选 PII 脱敏 | 在持久化前处理敏感输入 |
| 截取最近消息 | `raw_recent[-4:]` | 控制上下文长度 |
| 限制角色 | 仅 `user` / `assistant` | 排除未知角色 |
| 清理内容 | `strip()[:500]` | 去空白并限制单条长度 |
| 推导工作流状态 | `plan_requested/scene_ready/empty_scene` | 为后续流程提供状态 |
| 保存安全结果 | `_server_safety` | runner 进入 Graph 前可拒绝 |

## 2. Notebook 分单元格观察

### Cell 1：实现不含外部服务的最小预处理

- 输入：客户端字典与服务端身份；
- 依赖：无；
- 预期：产生新字典；
- 观察：只复刻结构处理，不冒充 PII 与内容安全实现。

```python
def prepare_request_minimal(data: dict, server_identity: dict) -> dict:
    prepared = dict(data)
    prepared["plan_mode"] = prepared.get("plan_mode") is True
    prepared["_server_access_context"] = dict(server_identity)
    prepared["message"] = str(prepared.get("message") or "")

    recent_messages = []
    raw_recent = prepared.get("recent_messages")
    if isinstance(raw_recent, list):
        for item in raw_recent[-4:]:
            if not isinstance(item, dict):
                continue
            role = str(item.get("role") or "").lower()
            if role not in {"user", "assistant"}:
                continue
            content = str(item.get("content") or "").strip()[:500]
            if content:
                recent_messages.append({"role": role, "content": content})

    prepared["recent_messages"] = recent_messages
    prepared["workflow_state"] = (
        "plan_requested"
        if prepared["plan_mode"]
        else "scene_ready"
        if isinstance(prepared.get("blueprint"), dict)
        else "empty_scene"
    )
    return prepared
```

代码解释：这段刻意保持与真实源码相同的 Python 结构，方便逐行对照；安全检查被明确排除，因为不能用几行示例假装生产安全逻辑。

### Cell 2：准备带噪声的请求

- 输入：多于4条历史消息、非法角色、空内容、字符串布尔值；
- 依赖：Cell 1；
- 预期：只保留末4项中合法且非空的消息；
- 观察：切片发生在角色过滤之前。

```python
raw_request = {
    "type": "user_message",
    "request_id": "req-1",
    "session_id": "session-1",
    "message": "生成住宅",
    "plan_mode": "true",
    "recent_messages": [
        {"role": "user", "content": "会被末4条切片排除"},
        {"role": "system", "content": "非法角色"},
        "不是字典",
        {"role": "assistant", "content": "  上一轮回答  "},
        {"role": "user", "content": "本轮补充"},
    ],
}

identity = {"user_id": "server-user", "scopes": ["public"]}
prepared = prepare_request_minimal(raw_request, identity)
prepared
```

代码解释：`"true" is True` 为假，所以 `plan_mode` 最终是 `False`。这比 `bool("false")` 更安全，因为任何非空字符串的 `bool()` 都为真。

### Cell 4：观察 `start_job()` 的调用边界

- 输入：预处理后的请求和假连接；
- 依赖：Cell 2；
- 预期：服务收到的正是 `prepared`；
- 观察：路由只负责调用，是否新建由服务返回的 `created` 决定。

```python
class FakeJob:
    def __init__(self, request_id: str, session_id: str):
        self.request_id = request_id
        self.session_id = session_id


class RecordingJobService:
    def __init__(self):
        self.calls = []

    async def start_job(self, payload: dict, subscriber: object):
        self.calls.append((payload, subscriber))
        job = FakeJob(payload["request_id"], payload["session_id"])
        return job, True


fake_connection = object()
job_service = RecordingJobService()
job, created = await job_service.start_job(prepared, fake_connection)

assert created is True
assert job_service.calls[0][0] is prepared
print(job.request_id, job.session_id, created)
```

代码解释：假服务记录调用参数，不执行后台任务。它验证的是 `agent_websocket()` 与服务层之间的接口契约。

### Cell 5：主动制造缺少请求编号的错误

- 输入：缺少 `request_id` 的请求；
- 依赖：无；
- 预期：观察明确的 `ValueError`；
- 排查方向：这是任务身份错误，尚未进入 Graph。

```python
def require_request_id(payload: dict) -> str:
    request_id = str(payload.get("request_id") or "")
    if not request_id:
        raise ValueError("request_id 不能为空")
    return request_id

try:
    require_request_id({"type": "user_message"})
except ValueError as exc:
    print(type(exc).__name__, str(exc))
```

代码解释：真实 `GenerationJobService.start_job()` 也先读取并检查 `request_id`。错误栈停在服务入口时，不应先去排查模型或节点。

## 3. 补充知识点

`_server_access_context` 和 `_server_safety` 以前导下划线标记“服务端内部字段”。这只是命名约定；真正的安全边界来自后端覆盖客户端值、持久化前清洗以及后续代码不信任客户端自报数据。
