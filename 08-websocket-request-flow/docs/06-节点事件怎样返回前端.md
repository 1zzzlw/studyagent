## 本章目标

本章结束时，你能区分 LangGraph 内部事件和 WebSocket 业务事件，知道节点开始/结束信息怎样经过翻译、持久化、广播和前端去重。

## 1. 两套事件语言

### LangGraph 内部事件

```python
{
    "event": "on_chain_start",
    "name": "classifier",
    "data": {"input": {...}},
}
```

或者：

```python
{
    "event": "on_chain_end",
    "name": "classifier",
    "data": {"output": {...}},
}
```

### WebSocket 业务事件

```python
{
    "protocol_version": "1.0",
    "type": "agent_step",
    "request_id": "req_xxx",
    "session_id": "session_xxx",
    "node": "classifier",
    "status": "running",
    "label": "意图分类",
    "detail": "分析用户意图",
}
```

前者服务于框架观测，后者服务于前端产品协议。WildAgent 没有把原始 LangGraph 事件直接推给浏览器。

## 2. 事件翻译的位置

`_handle_with_langgraph()` 遍历：

```text
async for event in graph.astream_events(...)
→ 读取 event / name
→ 只保留 _OUR_NODES 中的节点
→ on_chain_start：记录开始时间并发送 running agent_step
→ on_chain_end：读取 data.output、诊断和 Token Usage
→ 根据具体节点输出发送完成、审核、回答或蓝图事件
```

`_OUR_NODES` 同时包含固定节点和根据组件 Registry 生成的 `*_gen`、`*_val` 名称。

## 3. 事件怎样离开 Graph

```text
_emit_agent_step() / _send_event()
→ sink.send_json(payload)
→ DurableEventSink.send_json()
→ GenerationJobService.publish_event()
→ 可持久化事件：写 SQLite、增加 event_seq、广播
→ 非持久化事件：直接广播
→ subscriber.send_json(event)
→ 浏览器 agentBridge.onmessage
```

当前关键业务事件会持久化；`thinking_delta` 只有 `channel="progress"` 时持久化，普通 reasoning 增量直接广播。这个取舍避免把所有细碎 Token 都写入数据库。

## 4. 前端为什么还要 event_seq 去重

断线后可能发生：

```text
历史事件补发
+ 新的实时事件继续到达
```

前端为每个 `request_id` 保存最后处理的序号。如果新事件的 `event_seq` 小于或等于已处理序号，就跳过，避免重复更新同一轮 UI。

没有 `event_seq` 的瞬时事件不会进入这套持久化去重判断。

### Cell 2：把内部事件翻译成业务事件

- 依赖：Cell 1；
- 是否联网：否；
- 输入：内部事件、请求ID和会话ID；
- 输出：`agent_step` 或 `None`。

```python
KNOWN_NODE_NAMES = {"classifier", "chat", "generate"}


def translate_graph_event(
    event: dict,
    *,
    request_id: str,
    session_id: str,
) -> dict | None:
    node_name = str(event.get("name") or "")
    event_kind = event.get("event")

    if node_name not in KNOWN_NODE_NAMES:
        return None

    if event_kind == "on_chain_start":
        return {
            "type": "agent_step",
            "request_id": request_id,
            "session_id": session_id,
            "node": node_name,
            "status": "running",
            "detail": f"{node_name}开始执行",
        }

    if event_kind == "on_chain_end":
        output = event.get("data", {}).get("output", {})
        if not isinstance(output, dict):
            output = {}
        return {
            "type": "agent_step",
            "request_id": request_id,
            "session_id": session_id,
            "node": node_name,
            "status": "done",
            "detail": f"{node_name}完成",
            "node_output": output,
        }

    return None


business_events = [
    translated
    for event in internal_events
    if (
        translated := translate_graph_event(
            event,
            request_id="req_event_001",
            session_id="session_event_001",
        )
    ) is not None
]

for event in business_events:
    print(event)
```

### Cell 3：实现最小持久化与广播

- 依赖：第4章的 `DemoSubscriber`；
- 是否联网：否；
- 预期：持久化事件获得递增 `event_seq`。

```python
PERSISTED_TYPES = {
    "agent_step",
    "thinking_status",
    "agent_reply",
    "error",
}


class MemoryEventBus:
    def __init__(self):
        self.stored: dict[str, list[dict]] = {}
        self.subscribers: dict[str, list[DemoSubscriber]] = {}

    async def attach(self, request_id: str, subscriber: DemoSubscriber):
        self.subscribers.setdefault(request_id, []).append(subscriber)

    async def publish(self, request_id: str, payload: dict):
        if not request_id:
            raise ValueError("request_id不能为空")

        event = dict(payload)
        if event.get("type") in PERSISTED_TYPES:
            history = self.stored.setdefault(request_id, [])
            event["event_seq"] = len(history) + 1
            history.append(dict(event))

        for subscriber in self.subscribers.get(request_id, []):
            await subscriber.send_json(event)


event_bus = MemoryEventBus()
browser_one = DemoSubscriber("browser-one")
browser_two = DemoSubscriber("browser-two")

await event_bus.attach("req_event_001", browser_one)
await event_bus.attach("req_event_001", browser_two)

for event in business_events:
    await event_bus.publish("req_event_001", event)

print("历史：", event_bus.stored["req_event_001"])
print("浏览器一：", browser_one.messages)
print("浏览器二：", browser_two.messages)
```

### Cell 4：模拟前端 event_seq 去重

- 依赖：Cell 3；
- 是否联网：否；
- 预期：重复事件只处理一次。

```python
class DemoFrontend:
    def __init__(self):
        self.last_sequences: dict[str, int] = {}
        self.handled: list[dict] = []

    def receive(self, event: dict) -> bool:
        request_id = str(event.get("request_id") or "")
        sequence = event.get("event_seq")

        if request_id and isinstance(sequence, int):
            last_sequence = self.last_sequences.get(request_id, 0)
            if sequence <= last_sequence:
                return False
            self.last_sequences[request_id] = sequence

        self.handled.append(dict(event))
        return True


frontend = DemoFrontend()
first_stored_event = event_bus.stored["req_event_001"][0]

print("首次处理：", frontend.receive(first_stored_event))
print("重复处理：", frontend.receive(first_stored_event))
print("实际处理数量：", len(frontend.handled))

assert len(frontend.handled) == 1
```

## 6. 常见问题

### 为什么节点 end 事件不等于最终回答

每个节点都会结束。只有特定节点和最终状态会被转换成 `agent_reply`、`patch_proposal` 或 `blueprint_generated` 等终端业务事件。

### 为什么不是所有事件都落库

高频细粒度事件会放大存储量。当前实现持久化关键状态事件和 progress 增量，普通 reasoning 增量只实时广播。
