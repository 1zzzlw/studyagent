先看 WildAgent 当前模块怎样相互依赖，再学习模式；避免只凭目录名假设分层很干净。

## 1. 名义职责与真实情况

| 目录 | 主要职责 | 当前代表文件 |
| --- | --- | --- |
| `app/api` | HTTP/WebSocket 传输边界 | `ws_agent.py`、`sessions.py` |
| `app/services` | 用例、任务生命周期、交付 | `generation_job_service.py`、`agent_delivery.py`、`agent_service.py` |
| `app/agent` | Graph、节点、模型适配、运行上下文 | `graph.py`、`nodes/`、`model_client.py` |
| `app/spec` | 知识文件、切片、Embedding、Chroma 检索 | `loader.py`、`query_planner.py` |
| `app/tools` | 确定性校验与修复工具 | `spatial_tools.py`、`component_tools.py` |
| `app/config` | 配置对象与领域配置 | `domain_config.py` |
| `app/extensions` | 可选扩展能力 | `presence/` |
| `app/utils` | 边界清楚的通用处理 | Blueprint、JSON、心跳工具 |

名义主方向大致是：

```text
api → services → agent → spec/tools/utils
```

但当前源码还有反向依赖：`agent_service.py` 导入许多 `app.agent.*`，多个 `app.agent.nodes.*` 又在函数内部导入 `app.services.agent_service`。局部导入延迟了循环初始化，却没有消除双向认知依赖。

## 2. Notebook 分单元格观察

### Cell 1：读取选定源码

- 输入：`wildagent_root`；
- 依赖：第00章公共环境初始化 Cell；
- 预期：得到文件到文本的映射；
- 观察：只读文本，不执行模块顶层代码。

```python
selected_files = [
    "wild-server/app/api/ws_agent.py",
    "wild-server/app/services/agent_service.py",
    "wild-server/app/services/generation_job_service.py",
    "wild-server/app/agent/graph.py",
    "wild-server/app/agent/nodes/chat_node.py",
    "wild-server/app/spec/loader.py",
]

sources = {
    relative: (wildagent_root / relative).read_text(encoding="utf-8")
    for relative in selected_files
}

for relative, source in sources.items():
    print(relative, len(source.splitlines()), "行")
```

代码解释：字典推导式同时保留路径和源码；本章只扫描代表文件，不用一次加载整个仓库。

### Cell 2：提取 `from app... import ...`

- 输入：`sources`；
- 依赖：Cell 1；
- 预期：看到每个文件依赖的 `app.*` 模块；
- 观察：导入语句是一种静态依赖证据，但局部导入也需要匹配。

```python
import re

import_pattern = re.compile(r"^\s*from\s+(app(?:\.[A-Za-z_]\w*)+)\s+import\s+", re.MULTILINE)
imports_by_file = {
    relative: sorted(set(import_pattern.findall(source)))
    for relative, source in sources.items()
}

for relative, imports in imports_by_file.items():
    print("\n", relative)
    for imported in imports:
        print("  ->", imported)
```

代码解释：正则开头允许空白，所以函数内部的延迟导入也会被发现。`set` 去重，`sorted` 保证输出稳定。

### Cell 3：观察服务层与节点的双向依赖

- 输入：两个真实源码文本；
- 依赖：Cell 1；
- 预期：两个方向的断言都通过；
- 观察：这是“依赖回流”证据，不等同于 Python 已经报循环导入错误。

```python
service_source = sources["wild-server/app/services/agent_service.py"]
node_source = sources["wild-server/app/agent/nodes/chat_node.py"]

service_to_agent = "from app.agent.model_client import" in service_source
agent_to_service = "from app.services.agent_service import agent_service" in node_source

assert service_to_agent is True
assert agent_to_service is True
print("services.agent_service → agent.model_client：", service_to_agent)
print("agent.nodes.chat_node → services.agent_service：", agent_to_service)
```

代码解释：双向依赖会让初始化顺序、测试替换和拆分模块更困难。局部导入可以缓解导入时错误，但节点仍知道全局服务对象。

### Cell 4：用边列表表示依赖图

- 输入：简化模块边；
- 依赖：无；
- 预期：找出一对互相依赖的模块；
- 观察：有向边 `(A, B)` 表示 A 知道 B。

```python
dependency_edges = {
    ("api", "services"),
    ("api", "agent"),
    ("services", "agent.nodes"),
    ("services", "spec"),
    ("services", "tools"),
    ("agent.nodes", "services"),
    ("agent.nodes", "spec"),
}

def reverse_pairs(edges: set[tuple[str, str]]) -> list[tuple[str, str]]:
    pairs = []
    for source, target in edges:
        reverse = (target, source)
        if reverse in edges and source < target:
            pairs.append((source, target))
    return sorted(pairs)

print(reverse_pairs(dependency_edges))
```

代码解释：真实包名粒度不完全一致，所以最后用同粒度的两条边演示。依赖图的关键是方向，不是把所有文件画进一张图。

### Cell 5：主动制造错误路径

- 输入：拼错的源码文件；
- 依赖：`wildagent_root`；
- 预期：捕获 `FileNotFoundError`；
- 排查顺序：工作目录 → `wildagent_root` → 相对路径 → 当前分支文件名。

```python
wrong_path = wildagent_root / "wild-server/app/agent/missing_pattern.py"
try:
    wrong_path.read_text(encoding="utf-8")
except FileNotFoundError as exc:
    print(type(exc).__name__, exc.filename)
```

代码解释：源码导读的第一步永远是确认当前文件真实存在，不要用旧笔记中的路径继续推断。

## 3. 补充知识点

分层架构不是要求“上层永远不能调用下层”，而是控制依赖方向。若两个大模块互相知道对方的具体实现，局部修改更容易扩散。09最后一章会把这些事实整理为候选边界，但本模块不修改 WildAgent。
