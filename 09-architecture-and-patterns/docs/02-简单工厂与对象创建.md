# 第02章：简单工厂与对象创建

## 本章目标

理解 WildAgent 为什么把复杂对象创建集中到 `create_*()` 函数，并区分“简单工厂”与“缓存后的全局对象”。

## 前置知识

- 函数参数、默认值、关键字参数；
- 类与实例；
- 配置对象只描述参数，不等于已建立网络连接。

## 1. 当前源码证据

| 工厂 | 返回对象 | 调用者不必知道的细节 |
| --- | --- | --- |
| [`create_llm()`](../../../WildAgent/wild-server/app/agent/model_client.py) | `ReasoningChatOpenAI` | URL、超时、流式 usage、供应商思考字段 |
| [`create_search_client()`](../../../WildAgent/wild-server/app/agent/web/__init__.py) | `TavilySearchClient` 或 `None` | 开关、provider、API Key、构造异常 |
| `create_embedding_function()` | Embedding 实现 | 在线模型或受控 Hash fallback |
| `create_asset_storage()` | 本地资产存储 | 根目录和容量配置 |
| `create_component_generator()` | 一个异步节点函数 | 组件 Prompt、输出键、规则和校验字段 |

这些主要是“简单工厂函数”：调用者请求对象，工厂集中决定具体类和构造参数。它们不是必须通过继承实现的 GoF Factory Method。

`get_graph()` 还额外做了按键缓存，属于后续第09章的生命周期问题，不能仅因为名字以 `get_` 开头就叫工厂。

## 2. Notebook 分单元格观察

### Cell 1：定义配置与两种客户端

- 输入：无；
- 依赖：无；
- 预期：类只保存构造结果；
- 观察：具体客户端有不同字段，但调用者可共享公共操作。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class ClientConfig:
    provider: str
    model: str
    timeout: float = 60.0


class OpenAIStyleClient:
    def __init__(self, model: str, timeout: float):
        self.model = model
        self.timeout = timeout

    def describe(self) -> str:
        return f"openai-compatible:{self.model}@{self.timeout}s"


class LocalClient:
    def __init__(self, model: str):
        self.model = model

    def describe(self) -> str:
        return f"local:{self.model}"
```

代码解释：`frozen=True` 让配置实例不能被普通赋值修改。这里没有网络请求，只观察对象创建责任。

### Cell 2：把选择与构造集中到工厂

- 输入：`ClientConfig`；
- 依赖：Cell 1；
- 预期：不同 provider 返回不同具体类；
- 观察：业务调用者不再重复 `if provider`。

```python
def create_client(config: ClientConfig):
    if config.provider == "openai-compatible":
        return OpenAIStyleClient(config.model, config.timeout)
    if config.provider == "local":
        return LocalClient(config.model)
    raise ValueError(f"不支持的 provider: {config.provider}")

remote_client = create_client(ClientConfig("openai-compatible", "model-a", 30))
local_client = create_client(ClientConfig("local", "model-b"))

print(type(remote_client).__name__, remote_client.describe())
print(type(local_client).__name__, local_client.describe())
```

代码解释：工厂知道具体类；调用者只传配置并接收可用对象。切换配置改变创建结果，而不是让业务节点到处改构造代码。

### Cell 3：用正式单元测试验证工厂

- 输入：两个配置；
- 依赖：Cell 1、2；
- 预期：测试报告成功；
- 观察：既验证类型，也验证构造参数被正确传递。

```python
import unittest

class ClientFactoryTests(unittest.TestCase):
    def test_remote_client(self):
        client = create_client(ClientConfig("openai-compatible", "chat-x", 12))
        self.assertIsInstance(client, OpenAIStyleClient)
        self.assertEqual(client.timeout, 12)

    def test_local_client(self):
        client = create_client(ClientConfig("local", "tiny"))
        self.assertIsInstance(client, LocalClient)

suite = unittest.defaultTestLoader.loadTestsFromTestCase(ClientFactoryTests)
result = unittest.TextTestRunner(verbosity=2).run(suite)
assert result.wasSuccessful()
```

代码解释：只测试“创建规则”，不测试模型回答质量。对象创建测试与业务行为测试应该分开。

### Cell 4：观察每次调用是否创建新实例

- 输入：同一个配置调用两次；
- 依赖：Cell 2；
- 预期：内容相同，但对象身份不同；
- 观察：简单工厂默认不等于单例。

```python
shared_config = ClientConfig("local", "tiny")
first_client = create_client(shared_config)
second_client = create_client(shared_config)

assert first_client is not second_client
assert first_client.describe() == second_client.describe()
print(id(first_client), id(second_client))
```

代码解释：`is` 比较对象身份，`==` 通常比较值。WildAgent 的 `create_llm()` 也返回由调用方持有的新实例。

### Cell 5：主动传入未知 provider

- 输入：未支持配置；
- 依赖：Cell 2；
- 预期：捕获明确 `ValueError`；
- 排查方向：配置值 → 工厂分支 → 供应商实现是否已注册。

```python
try:
    create_client(ClientConfig("unknown", "model-x"))
except ValueError as exc:
    print(type(exc).__name__, str(exc))
```

代码解释：本例选择“失败得明确”。WildAgent 的 `create_search_client()` 对禁用、缺 Key 或未知 provider 返回 `None`，因为调用者设计了回退到本地知识的路径；错误策略取决于业务语义。

## 3. 补充知识点

工厂解决的是“怎么创建”，不是“对象怎样执行”。`create_llm()` 返回的对象随后仍由 `invoke_llm()` 或 `stream_llm()` 调用。11模块会深入模型工厂，本章只学习架构角色。
