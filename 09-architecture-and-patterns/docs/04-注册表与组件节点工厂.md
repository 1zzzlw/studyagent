# 第04章：注册表与组件节点工厂

## 本章目标

理解 `ComponentConfig → COMPONENT_REGISTRY → 节点工厂 → graph.add_node()` 怎样把重复的组件节点变成数据驱动结构。

## 前置知识

- `dataclass`、字典和列表；
- 函数可以作为返回值；
- 第02章的工厂概念。

## 1. 当前 WildAgent 主链

只读源码：

- [`component_registry.py`](../../../WildAgent/wild-server/app/agent/component_registry.py)：组件元数据中心；
- [`base_component_node.py`](../../../WildAgent/wild-server/app/agent/nodes/base_component_node.py)：创建通用 gen/val 节点；
- [`graph.py`](../../../WildAgent/wild-server/app/agent/graph.py)：遍历注册表并把节点加入 Graph。

```text
ComponentConfig
→ COMPONENT_REGISTRY[component_type]
→ get_implemented_components()
→ create_component_generator(config)
→ create_component_validator(config)
→ graph.add_node("door_gen", ...)
→ graph.add_node("door_val", ...)
→ graph.add_edge("door_gen", "door_val")
```

注册表保存差异，工厂保存共同行为。门、窗、屋顶等组件不再各复制一整套生成与校验函数。

## 2. `ComponentConfig` 保存了什么

| 分类 | 代表字段 | 被谁使用 |
| --- | --- | --- |
| 身份 | `component_type`、`label` | Graph 节点名和日志 |
| RAG | `entity_type`、`rag_extra_queries` | 组件知识检索 |
| 输出 | `output_key`、`is_list`、`is_element` | State/Blueprint 写入 |
| 校验 | `required_fields`、`optional_fields` | 通用验证器 |
| 触发 | `skip_keywords`、`need_keywords` | 组件建议归一化 |
| 规则 | `extra_rules`、`output_format_hint` | Prompt 构造 |
| 调度 | `priority`、`dependencies`、`implemented` | 可用组件与依赖 |

`field(default_factory=list)` 为每个配置创建独立列表，避免多个实例共享同一个可变默认值。

## 3. Notebook 分单元格观察

### Cell 1：定义最小组件配置和注册表

- 输入：无；
- 依赖：无；
- 预期：注册表按组件类型查找配置；
- 观察：键与 `component_type` 应一致。

```python
from dataclasses import dataclass, field

@dataclass
class MiniComponentConfig:
    component_type: str
    label: str
    required_fields: list[str] = field(default_factory=list)
    implemented: bool = True


mini_registry = {
    "door": MiniComponentConfig("door", "门", ["id", "parentWall"]),
    "window": MiniComponentConfig("window", "窗", ["id", "parentWall"]),
}

assert mini_registry["door"].label == "门"
mini_registry
```

代码解释：注册表是普通字典，不是特殊框架对象。它的价值来自“所有可用类型有统一配置形状”。

### Cell 2：用配置生成节点闭包

- 输入：单个组件配置；
- 依赖：Cell 1；
- 预期：返回一个记住该配置的函数；
- 观察：外层函数结束后，内层函数仍能访问 `config`。

```python
def create_mini_generator(config: MiniComponentConfig):
    def generate(state: dict) -> dict:
        return {
            "node": f"{config.component_type}_gen",
            "label": config.label,
            "required_fields": list(config.required_fields),
            "input_message": state.get("user_message", ""),
        }

    generate.__name__ = f"generate_{config.component_type}"
    return generate

door_generator = create_mini_generator(mini_registry["door"])
print(door_generator.__name__)
print(door_generator({"user_message": "生成一个入口"}))
```

代码解释：`generate` 是闭包，捕获了本次调用的 `config`。真实工厂返回异步节点，并把配置用于 RAG、Prompt、解析和 State 返回。

### Cell 3：批量生成 Graph 节点表

- 输入：整个注册表；
- 依赖：Cell 1、2；
- 预期：得到 `door_gen` 和 `window_gen`；
- 观察：建图代码不需要写两套业务函数。

```python
def build_node_table(registry: dict[str, MiniComponentConfig]) -> dict[str, object]:
    return {
        f"{component_type}_gen": create_mini_generator(config)
        for component_type, config in registry.items()
        if config.implemented
    }

node_table = build_node_table(mini_registry)
assert set(node_table) == {"door_gen", "window_gen"}
assert node_table["window_gen"]({})["label"] == "窗"
print(node_table)
```

代码解释：真实 `graph.py` 除了生成器，还创建 `*_val` 校验节点和 `gen → val` 边。这里先观察注册表驱动的数量变化。

### Cell 4：新增配置并观察扩展效果

- 输入：第三个配置；
- 依赖：Cell 3；
- 预期：节点表自动多出 `roof_gen`；
- 观察：新增数据可以复用现有工厂，但真实功能仍要求规则、输出和测试齐全。

```python
extended_registry = dict(mini_registry)
extended_registry["roof"] = MiniComponentConfig("roof", "屋顶", ["id", "roofType"])
extended_nodes = build_node_table(extended_registry)

assert set(extended_nodes) == {"door_gen", "window_gen", "roof_gen"}
print(sorted(extended_nodes))
```

代码解释：`dict(mini_registry)` 避免修改前一个 Cell 的注册表。数据驱动降低重复，不代表“加一行就自动完成业务实现”。

### Cell 5：主动制造键与配置不一致

- 输入：错误注册表；
- 依赖：Cell 1；
- 预期：校验函数抛出 `ValueError`；
- 排查方向：字典键 → `component_type` → Graph 节点名 → State 输出键。

```python
def validate_registry(registry: dict[str, MiniComponentConfig]) -> None:
    for key, config in registry.items():
        if key != config.component_type:
            raise ValueError(f"注册键 {key!r} 与 component_type {config.component_type!r} 不一致")

broken_registry = {"door": MiniComponentConfig("window", "窗")}
try:
    validate_registry(broken_registry)
except ValueError as exc:
    print(type(exc).__name__, str(exc))
```

代码解释：注册表把许多行为连接到同一个字符串身份，身份漂移会同时影响节点、Prompt、State 和前端诊断，因此需要集中验证。

## 4. 补充知识点

注册表不是数据库，也不是依赖注入容器。WildAgent 的 `COMPONENT_REGISTRY` 是进程内配置字典。它减少节点文件数量，但自身包含大量业务规则，规模继续增长时仍可能需要按领域拆分并在入口组合。
