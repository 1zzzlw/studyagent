# 第07章：高阶函数与节点包装

## 本章目标

读懂 `graph.py` 的 `_planned_node(step_type, node)`：函数怎样接收另一个函数、返回新函数，并在不修改原节点的情况下补充执行计划状态。

## 前置知识

- 函数可以赋值、传参和返回；
- 闭包；
- `async def`、`await` 与 `inspect.isawaitable()`。

## 1. 真实源码的作用

只读函数：[`graph.py`](../../../WildAgent/wild-server/app/agent/graph.py) 中的 `_planned_node()`。

```text
原节点 node(state)
→ _planned_node("architecture", node)
→ 返回新的 async run(state)
→ 执行原节点
→ 把结果转换为 dict
→ complete_execution_step(...)
→ 合并计划步骤更新
```

建图时可以看到：

```text
graph.add_node("architecture", _planned_node("architecture", architecture_planner))
graph.add_node("material_plan", _planned_node("material_plan", material_planner))
graph.add_node("skeleton", _planned_node("skeleton", skeleton_generator))
```

这具有 Decorator 模式的作用，但没有使用 `@decorator` 语法。更准确地说，它是“高阶函数包装节点”。

## 2. Notebook 分单元格观察

### Cell 1：先证明函数也是对象

- 输入：一个普通函数；
- 依赖：无；
- 预期：变量可以引用并调用函数；
- 观察：括号决定“传函数”还是“立即调用”。

```python
def original_node(state: dict) -> dict:
    return {"value": state.get("value", 0) + 1}

node_reference = original_node
assert node_reference is original_node
print(node_reference({"value": 2}))
```

代码解释：`original_node` 是函数对象，`original_node(...)` 才是调用结果。Graph 注册节点时接收的是前者。

### Cell 2：定义计划完成更新

- 输入：步骤类型与节点结果；
- 依赖：无；
- 预期：只返回额外字段；
- 观察：包装器可以把横切逻辑与业务节点分开。

```python
def complete_step(state: dict, step_type: str, result: dict) -> dict:
    if not state.get("plan_mode"):
        return {}
    completed = list(state.get("completed_steps", []))
    completed.append(step_type)
    return {"completed_steps": completed}
```

代码解释：真实 `complete_execution_step()` 会读取执行计划并更新具体步骤状态；本例只保留“计划模式才补更新”的边界。

### Cell 3：实现同步/异步都能包装的节点

- 输入：步骤名和原节点函数；
- 依赖：Cell 2；
- 预期：返回新的异步函数；
- 观察：闭包捕获 `step_type` 和 `node`。

```python
import inspect

def planned_node(step_type: str, node):
    async def run(state: dict) -> dict:
        result = node(state)
        if inspect.isawaitable(result):
            result = await result
        normalized = dict(result or {})
        normalized.update(complete_step(state, step_type, normalized))
        return normalized

    run.__name__ = f"planned_{step_type}"
    return run
```

代码解释：先调用原节点，再判断返回值是否需要 `await`。`dict(result or {})` 让 `None` 变成空字典；`update()` 把计划状态加入本次节点返回。

### Cell 4：观察包装前后差异

- 输入：同一个原节点与两种 `plan_mode`；
- 依赖：Cell 1～3；
- 预期：业务结果相同，计划模式额外返回步骤；
- 观察：原函数没有被修改。

```python
wrapped = planned_node("architecture", original_node)

normal_result = await wrapped({"value": 2, "plan_mode": False})
plan_result = await wrapped({"value": 2, "plan_mode": True, "completed_steps": []})

assert normal_result == {"value": 3}
assert plan_result == {"value": 3, "completed_steps": ["architecture"]}
assert original_node({"value": 2}) == {"value": 3}
print(wrapped.__name__, normal_result, plan_result)
```

代码解释：包装器增强返回值，而原节点仍只处理自己的业务。`__name__` 被设置后，日志和 Graph 调试更容易辨认。

### Cell 5：验证异步节点也能复用包装器

- 输入：一个异步节点；
- 依赖：Cell 3；
- 预期：结果被正确等待并增强；
- 观察：调用方式由包装器统一。

```python
async def async_material_node(state: dict) -> dict:
    return {"material": state.get("material", "default")}

wrapped_async = planned_node("material_plan", async_material_node)
async_result = await wrapped_async({"plan_mode": True, "material": "brick"})

assert async_result == {
    "material": "brick",
    "completed_steps": ["material_plan"],
}
print(async_result)
```

代码解释：`inspect.isawaitable()` 让包装器兼容同步和异步可调用对象，这与当前 WildAgent 实现一致。

### Cell 6：主动返回错误形状

- 输入：返回无法转换为字典的列表；
- 依赖：Cell 3；
- 预期：捕获 `TypeError` 或 `ValueError`；
- 排查方向：节点返回值 → State 局部更新是否为 dict → 包装器归一化位置。

```python
def broken_node(state: dict):
    return ["不是键值对"]

try:
    await planned_node("broken", broken_node)({"plan_mode": True})
except (TypeError, ValueError) as exc:
    print(type(exc).__name__, str(exc))
```

代码解释：包装器统一了调用方式，但不能把任意错误返回自动变成合法 State 更新。节点返回契约仍需测试。

## 3. 补充知识点

闭包会保留对外层对象的引用。若在循环里直接创建 `lambda` 并引用循环变量，可能出现所有函数都使用最后一个值的“晚绑定”问题。WildAgent 通过每次调用工厂并把 `config` 作为参数进入新作用域，避免了这类共享。
