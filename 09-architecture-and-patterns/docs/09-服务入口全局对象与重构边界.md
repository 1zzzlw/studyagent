## 1. `AgentService`：Facade，也带着全局依赖代价

[`agent_service.py`](../../../WildAgent/wild-server/app/services/agent_service.py) 的 `AgentService` 组装：

```text
SpecLoader + Embedding/RAG
+ 普通/思考 LLM
+ Tools
+ Prompt
+ 结构化解析
+ 校验流水线
→ query_structured()
```

从调用者角度，它具有 Facade/Service Layer 的作用：用一个入口隐藏许多子系统。

但要看当前真实使用：

- `ws_agent._handle_with_langchain()` 仍调用 `agent_service.query_structured()`，这不是当前持久 LangGraph 主分支；
- `patch_node` 当前仍使用 `query_structured()`；
- 多个生成节点在函数内部导入全局 `agent_service`，主要读取 `spec_loader`；
- `agent_service.py` 自己又导入大量 `app.agent.*`、`app.spec.*` 和 `app.tools.*`。

所以它既是统一入口，也是 Service Locator/全局共享对象式依赖，并造成 `services ↔ agent.nodes` 的依赖回流。

前端 [`agentBridge.ts`](../../../WildAgent/wild-web/src/agent/agentBridge.ts) 也具有通信 Facade 的作用：组件只调用 `sendUserMessage()` 等方法，Bridge 在内部管理 WebSocket、协议对象、心跳、恢复、事件分发和多个 Store。文件末尾的 `agentBridge = new AgentBridge()` 则让它成为前端模块级单例。它降低了 UI 调用难度，也让这个类承担了较多职责。

## 2. `commit_generation_result()`：单一交付入口

[`agent_delivery.py`](../../../WildAgent/wild-server/app/services/agent_delivery.py) 把下面顺序集中起来：

```text
汇总最后一次校验
→ 拒绝未完成/有错误/警告过多的结果
→ 保存 .wild
→ 返回 BlueprintDelivery
→ 调用者再发送 blueprint_generated / agent_reply
```

它更接近“统一用例入口/Transaction Script”，不必强行叫经典 Facade。重要的是所有提交都经过同一门禁，测试能证明失败时不会发送成功结果。

## 3. 模块级实例与 Graph 缓存

| 源码 | 生命周期判断 |
| --- | --- |
| `agent_service = AgentService()` | 导入模块时创建的全局实例 |
| `generation_job_service = GenerationJobService()` | 模块级任务服务实例 |
| `presence_service = WebSocketConnectionRegistry()` | 当前进程 Presence 实例 |
| `style_registry = StyleRegistry()` | 模块级注册表访问对象 |
| `agentBridge = new AgentBridge()` | 前端模块级通信实例 |
| `_graphs[cache_key]` + `get_graph()` | 按 callback/checkpointer 身份缓存，多键实例 |
| `get_domain_config()` | 懒加载单例式配置 |

`get_graph()` 不是严格单例：不同 `enable_callback` 或不同 checkpointer 身份可能得到不同 Graph，更接近 Multiton/带键缓存。

## 4. `_runner` 不是通知，而是被保存的函数对象

你看到的两行：

```text
await self._runner(sink, job.payload, resume)
→ _run_persistent_langgraph(sink, payload, resume)
```

中间没有消息队列、事件总线或 LangGraph 通知。连接在服务启动时就已经建立：

```text
FastAPI lifespan
→ startup_generation_jobs()
→ generation_job_service.startup(_run_persistent_langgraph)
→ self._runner = runner
```

Python 函数也是对象。调用 `startup(_run_persistent_langgraph)` 时没有括号，所以传入的是函数对象，而不是执行结果。`GenerationJobService.startup()` 把这个对象保存到实例字段 `self._runner`。

用户请求到来后：

```text
start_job()
→ _spawn(job, resume=False)
→ asyncio.create_task(self._run_job(...))
→ _run_job 创建 DurableEventSink
→ await self._runner(sink, job.payload, resume)
```

此时 `self._runner` 仍指向 `_run_persistent_langgraph`，所以调用它就等价于：

```python
await _run_persistent_langgraph(sink, job.payload, resume)
```

三个位置参数按顺序对应：

| `_run_job()` 传入 | runner 形参 | 含义 |
| --- | --- | --- |
| `sink` | `sink` | 持久事件输出适配器 |
| `job.payload` | `payload` | 原请求与恢复数据 |
| `resume` | `resume` | 新任务还是断点恢复 |

源码还声明了结构化类型：

```python
JobRunner = Callable[[Any, dict, bool], Awaitable[None]]
```

它表示 runner 必须是“接收三个参数、调用后返回可等待对象”的函数。这里同时具有三种理解角度：

- Callback：服务在后台任务真正执行时回调它；
- Strategy：测试或其他启动入口可以传入另一个同签名 runner；
- Dependency Injection：`GenerationJobService` 不直接 import `ws_agent._run_persistent_langgraph`，而由外部启动代码注入具体实现。

它不是 Observer：这里只保存一个 `_runner` 并直接 `await`，没有订阅者列表和广播。真正的 Observer 式结构是 `_subscribers` 与 `_broadcast()`。

这样设计的主要价值是避免 `generation_job_service.py` 反向导入 API 层的 `ws_agent.py`，同时单元测试可以传入假 runner。

## 5. Notebook 分单元格观察

### Cell 1：写一个统一交付入口

- 输入：校验状态与保存函数；
- 依赖：无；
- 预期：先门禁，再保存，再返回交付对象；
- 观察：调用者不用重复顺序规则。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class MiniDelivery:
    filename: str
    reply: str


def commit_result(status: str, error_count: int, save) -> MiniDelivery:
    if status != "complete" or error_count > 0:
        raise ValueError("校验未通过，禁止保存")
    filename = save()
    return MiniDelivery(filename, f"已保存 {filename}")
```

代码解释：函数把一组必须保持顺序的步骤变成单一入口。真实代码使用专属异常区分校验拒绝和保存失败。

### Cell 2：验证失败时绝不保存

- 输入：记录调用次数的保存函数；
- 依赖：Cell 1；
- 预期：合法结果保存一次，非法结果不增加次数；
- 观察：这是边界测试，不是只测返回文本。

```python
save_calls = []

def fake_save() -> str:
    save_calls.append("save")
    return "scene.wild"

delivery = commit_result("complete", 0, fake_save)
assert delivery.filename == "scene.wild"
assert save_calls == ["save"]

try:
    commit_result("partial", 1, fake_save)
except ValueError as exc:
    print(type(exc).__name__, str(exc))

assert save_calls == ["save"]
print("非法结果没有落盘")
```

代码解释：门禁失败发生在副作用之前。真实 `test_agent_delivery.py` 与 `test_generation_commit.py` 就在保护这种交付契约。

### Cell 3：观察按键缓存不是单例

- 输入：两个 cache key；
- 依赖：无；
- 预期：相同键返回同一对象，不同键返回不同对象；
- 观察：缓存键是生命周期的一部分。

```python
graph_cache: dict[tuple[bool, int | None], object] = {}

def get_cached_graph(enable_callback: bool, checkpointer=None):
    key = (enable_callback, id(checkpointer) if checkpointer is not None else None)
    if key not in graph_cache:
        graph_cache[key] = object()
    return graph_cache[key]

plain_a = get_cached_graph(False)
plain_b = get_cached_graph(False)
callback_graph = get_cached_graph(True)

assert plain_a is plain_b
assert plain_a is not callback_graph
print(len(graph_cache), list(graph_cache))
```

代码解释：严格 Singleton 通常只有一个实例；这里每个键最多一个实例。真实 Graph 还把 checkpointer 的 `id()` 放进键。

### Cell 4：主动观察全局对象污染测试

- 输入：共享可变对象；
- 依赖：无；
- 预期：第二段代码能看到第一段留下的状态；
- 排查方向：模块级实例 → 测试是否替换/恢复 → 缓存是否清空。

```python
global_service_state = {"calls": 0}

def use_global_service() -> int:
    global_service_state["calls"] += 1
    return global_service_state["calls"]

first = use_global_service()
second = use_global_service()
assert (first, second) == (1, 2)
print("共享状态：", global_service_state)

global_service_state["calls"] = 0
```

代码解释：模块级单例方便调用，却让测试顺序和热重载更敏感。最后显式恢复，避免污染后续 Cell。

### Cell 7：先证明传入的是函数对象

- 输入：一个异步函数；
- 依赖：无；
- 预期：赋值不会执行函数；
- 观察：有括号才会产生协程对象并进入调用过程。

```python
async def demo_runner(sink, payload: dict, resume: bool) -> None:
    await sink.send_json({
        "type": "runner_called",
        "request_id": payload["request_id"],
        "resume": resume,
    })

assert runner_reference is demo_runner
print(runner_reference.__name__)
```

代码解释：`demo_runner` 是函数对象；`demo_runner(...)` 才会调用函数并返回协程。`startup(_run_persistent_langgraph)` 使用的是前一种形式。

### Cell 8：实现最小 runner 注册与回调

- 输入：一个满足三参数协议的函数；
- 依赖：Cell 7；
- 预期：`startup()` 保存对象，`run_job()` 再调用同一个对象；
- 观察：注册和执行发生在不同时间。

```python
class MiniJobService:
    def __init__(self):
        self._runner = None

    async def startup(self, runner) -> None:
        self._runner = runner

    async def run_job(self, sink, payload: dict, resume: bool) -> None:
        if self._runner is None:
            raise RuntimeError("runner 尚未配置")
        await self._runner(sink, payload, resume)
```

代码解释：`startup()` 没有执行 runner，只保存引用；`run_job()` 才用括号调用它。真实服务还会创建任务、维护状态并处理暂停和异常。

### Cell 9：运行并观察参数映射

- 输入：记录事件的假 sink；
- 依赖：Cell 7～8；
- 预期：事件包含 request_id 与 resume；
- 观察：三个位置参数如何进入 runner。

```python
class RecordingSink:
    def __init__(self):
        self.events = []

    async def send_json(self, payload: dict) -> None:
        self.events.append(payload)


service = MiniJobService()
sink = RecordingSink()

await service.startup(demo_runner)
await service.run_job(sink, {"request_id": "req-1"}, False)

assert sink.events == [{

    "request_id": "req-1",

```

代码解释：Notebook 顶层可以直接 `await`。这段代码完整复现了“函数对象注册 → 实例字段保存 → 后台边界调用”，没有使用通知机制。

## 6. 当前可借鉴边界与耦合风险

### 可借鉴

- 搜索客户端用 Protocol + Factory 隔离真实服务与 Mock；
- 组件注册表 + 节点工厂减少重复 gen/val 文件；
- DurableEventSink 让 Graph 不绑定物理连接；
- ContextVar 把不可序列化资源挡在 GenerationState 外；
- runner 注入让任务服务不必反向导入 WebSocket API 实现；
- 交付门禁集中，成功事件只能在保存成功后发出。
- 前端 AgentBridge 隔离 UI 与底层 WebSocket 协议细节。

### 需要警惕

- `ws_agent.py` 同时承担接入、Graph 编排、事件翻译和交付；
- `AgentService` 体积大，节点又反向读取其全局实例；
- `GenerationJobService` 同时管理任务、SQLite、Checkpoint、订阅者和广播；
- `AgentBridge` 同时管理连接、协议、请求上下文、恢复、产物和 Store 更新；
- 模块导入时创建重对象，会增加启动、测试和配置热更新复杂度；
- 继承 LangChain 受保护方法的兼容适配对依赖版本敏感。

这些是下一次优化的候选边界，不是要求现在同时重构。先用调用链、回归测试和实际问题选择一个最小目标。

## 8. 补充知识点

设计模式是描述协作关系的语言，不是质量认证。一个结构可以同时具有 Facade 的便利和 Service Locator 的隐藏依赖；判断时必须同时写收益、代价和源码证据。

`Callable[[Any, dict, bool], Awaitable[None]]` 只做静态类型说明，运行时不会自动验证函数签名。真正传错参数数量时，会在调用 `_runner(...)` 才抛出 `TypeError`。如果需要更强的运行时协议，可以再使用 `Protocol`，但当前单一回调没有必要为此增加抽象。
