## 1. 四种数据形状

### 节点局部返回

```python
{
    "design_document": {...},
    "resolved_design": {...},
    "design_review_status": "pending",
}
```

它表示一个节点本轮写入哪些 channel。

### Checkpoint 中的完整 State

```python
snapshot = await graph.aget_state(graph_config)
snapshot.values
snapshot.next
```

`values` 是所有字段的当前快照；`next` 是下一待执行节点，不是历史节点列表。

### LangGraph v2 事件

```python
{
    "event": "on_chain_end",
    "name": "architecture",
    "data": {"output": {...}},
    # 还可能有 run_id、parent_ids、tags、metadata
}
```

事件是观测信封。WildAgent 过滤 `_OUR_NODES` 后，才把节点事件中的 `data.output` 当作该节点输出。

### 前端持久事件

```python
{
    "type": "design_review_required",
    "request_id": "...",
    "document": {...},
    "resolved": {...},
    "preview_url": "...",
}
```

这是 WildAgent 自己的 WebSocket 协议，由服务层从 snapshot 转换而来，不是 LangGraph 原生事件。

## 2. 四级验证证据

| 证据级别 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 静态源码 | 节点注册、字段读写、路由代码存在 | 运行时一定经过 |
| 微型图 | LangGraph 的 State/interrupt/事件语义 | WildAgent 全依赖可运行 |
| 项目回归测试 | 契约、版本、路由、恢复的已覆盖行为 | 真实模型输出质量 |
| 真实端到端 | 实际配置、模型、数据库、前端共同工作 | 所有输入都稳定 |

若遇到 `WinError 10106`，只说明真实异步运行被主机 Winsock 阻断。静态证据和微型纯路径结果仍可分别记录，但不能写成端到端通过。

## 3. 这次难点的最终判断

| 问题 | 当前判断 | 关键证据 |
| --- | --- | --- |
| 节点调用链是否明确 | 是 | graph 条件边、Send、Job runner、WS resume |
| 中间设计是否成为正式对象 | 是 | DesignDocument、Repository、ResolvedDesign |
| 用户修改是否能回到同一流程 | 是 | interrupt + Command + revision check |
| SVG 与 Blueprint 是否可追溯 | 是 | revision + designHash |
| 所有 State 是否已强类型化 | 否 | GenerationState 仍含大量 dict |
| 所有设计字段是否已被直接消费 | 否 | approved 文档仍编译到 architecture_plan/design_brief |
| 建筑质量是否因此自动完美 | 否 | 仍依赖 planner、编译、组件生成和 validator 质量 |

所以更准确的说法是：**Agent 工作流与中间设计状态已经建立了正确主干；旧生成节点的兼容协议与真实运行质量仍需继续收口和验证。**

## 错误实验

从一个 `on_chain_end` 事件中只取 `data.output`，把它误命名成 `complete_state`，然后检查其中是否仍有最初的 `user_message` 和前序节点字段。缺失这些字段时，应把变量改名为 `node_output`；完整 State 应从最终调用结果或 checkpoint snapshot 获取。

## 常见误判

- 看见 State 有字段，就说下游已经使用；
- 看见 Prompt 包含字段，就说约束已强制执行；
- 看见 `on_chain_end`，就把 `data.output` 当完整 State；
- 看见 Job 为 waiting，就以为 checkpoint 一定存在；
- 看见设计测试通过，就说真实模型生成质量已经验证；
- 因主机 `WinError 10106`，把静态源码结论也判成业务失败。
