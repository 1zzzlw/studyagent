## 1. 一次模型调用的五层

```text
.env 配置
→ Client Factory
→ Chat Model Client
→ Invocation Layer
→ AIMessage / 统一结果
→ 业务节点
```

| 层 | 保存什么 | 不应该负责什么 |
|---|---|---|
| 配置 | 模型名、地址、Key、超时 | 发送请求 |
| Client Factory | 把配置变成模型对象 | 编写业务 Prompt |
| Model Client | 序列化消息、请求服务、生成响应对象 | 决定业务路由 |
| Invocation Layer | 调用方式、超时、重试、结果归一化 | 建筑业务修复 |
| 业务节点 | 准备业务消息并消费统一结果 | 重复解析供应商响应 |

## 2. 创建对象不等于调用模型

```python
llm = ChatOpenAI(...)
```

只创建并配置对象。真正发请求的是：

```python
llm.invoke(messages)
await llm.ainvoke(messages)
llm.stream(messages)
llm.astream(messages)
```

这和07模块中的 `OpenAI(...)` 与 `client.embeddings.create(...)` 是同一层次关系。

## 3. 四种调用方式

| 方法 | 是否异步 | 是否流式 | 返回形态 |
|---|---|---|---|
| `invoke()` | 否 | 否 | 一个完整 `AIMessage` |
| `ainvoke()` | 是 | 否 | `await` 后得到一个完整 `AIMessage` |
| `stream()` | 否 | 是 | 迭代多个 `AIMessageChunk` |
| `astream()` | 是 | 是 | 异步迭代多个 `AIMessageChunk` |

异步不等于流式：`ainvoke()` 仍然等完整结果；`stream()` 虽然同步，却能逐块返回。

### Cell 4：用假的调用器看清职责边界

- 依赖：无；
- 是否联网：否；
- 输入：一个只记录调用次数的假模型；
- 预期：创建假对象时计数为0，调用后计数为1。

```python
class CountingChatModel:
    def __init__(self):
        self.call_count = 0

    def invoke(self, messages):
        self.call_count += 1
        return {"content": "这是离线假回答", "messages": messages}


fake_llm = CountingChatModel()
print("创建后调用次数：", fake_llm.call_count)

fake_response = fake_llm.invoke([("human", "你好")])
print("调用后调用次数：", fake_llm.call_count)
print("假响应：", fake_response)
```

## 5. 主动错误实验

故意把“客户端对象”当成“模型响应”读取：

```python
try:
    print(llm.content)
except AttributeError as exc:
    print("预期对象边界错误：", exc)
```

这个错误不会联网。`llm` 是客户端，只有 `invoke()` 返回的 `AIMessage` 才有本次回答的 `content`。请把这句话写进 Notebook，确认自己没有把“创建对象”和“获得回答”混成一步。
