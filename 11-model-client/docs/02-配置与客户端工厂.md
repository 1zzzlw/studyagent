# 第2章：配置与客户端工厂

## 本章目标

把散落的环境变量读取集中为一个配置对象，再通过工厂函数创建 `ChatOpenAI`。

## 前置知识

- 已运行第1章的公共初始化和环境加载 Cell；
- 知道本模块只使用 `LLM_*`，不使用 `EMBEDDING_*`；
- 了解 Python `dataclass` 的基本字段含义。

## 1. 为什么需要工厂

如果每个节点都写一次：

```python
ChatOpenAI(model=..., base_url=..., api_key=...)
```

很容易出现某些节点忘记超时、某些节点使用旧模型、某些节点把 Embedding Key 传给聊天模型。工厂函数把对象创建规则收敛到一个入口。

```text
环境变量 → ChatSettings → create_chat_model() → ChatOpenAI
```

## 2. 配置项的责任

| 配置 | 影响 | 修改后是否需要重建 Chroma |
|---|---|---|
| `LLM_MODEL` | 聊天输出能力 | 否 |
| `LLM_BASE_URL` | 请求发往哪个聊天服务 | 否 |
| `LLM_API_KEY` | 聊天服务鉴权 | 否 |
| `timeout` | 单次等待上限 | 否 |
| `max_retries` | SDK内部重试次数 | 否 |
| `temperature` | 输出随机性 | 否 |

聊天配置变化不影响已有向量空间，因为 Chroma 使用07模块的 `EMBEDDING_*`。

## 3. Notebook 分单元格练习

在 Notebook 中建立 `# 第2章：配置与客户端工厂`。

### Cell 1：定义最小配置对象

- 依赖：第1章 Cell 1；
- 是否联网：否；
- 预期：只保存配置，不创建模型对象。

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class ChatSettings:
    model: str
    base_url: str
    api_key: str
    timeout: float = 60.0
    max_retries: int = 0

    @classmethod
    def from_env(cls):
        values = {
            "model": os.getenv("LLM_MODEL", "").strip(),
            "base_url": os.getenv("LLM_BASE_URL", "").strip(),
            "api_key": os.getenv("LLM_API_KEY", "").strip(),
        }
        missing = [name for name, value in values.items() if not value]
        if missing:
            raise RuntimeError(f"缺少聊天配置字段：{', '.join(missing)}")
        return cls(**values)


chat_settings = ChatSettings.from_env()
print("配置类型：", type(chat_settings).__name__)
print("模型：", chat_settings.model)
print("地址：", chat_settings.base_url)
print("超时：", chat_settings.timeout)
```

不要输出 `chat_settings.api_key`。

### Cell 2：编写客户端工厂

- 依赖：Cell 1；
- 是否联网：否；
- 输入：`ChatSettings`；
- 输出：一个由调用方持有的 `ChatOpenAI`。

```python
def create_chat_model(
    settings: ChatSettings,
    *,
    streaming: bool = False,
) -> ChatOpenAI:
    return ChatOpenAI(
        model=settings.model,
        base_url=settings.base_url,
        api_key=settings.api_key,
        temperature=0,
        timeout=settings.timeout,
        max_retries=settings.max_retries,
        streaming=streaming,
        stream_usage=streaming,
    )
```

### Cell 3：分别创建非流式与流式对象

- 依赖：Cell 2；
- 是否联网：否；

normal_llm = create_chat_model(chat_settings, streaming=False)

### Cell 4：用假配置验证门禁

- 依赖：Cell 1；
- 是否联网：否；
- 主动错误：临时清空 `LLM_MODEL`；
- 预期：在创建 Client 前就失败。

```python
original_model = os.environ.get("LLM_MODEL")
os.environ["LLM_MODEL"] = ""

try:
    ChatSettings.from_env()
except RuntimeError as exc:
    print("预期配置错误：", exc)
else:
    raise AssertionError("空模型名应该被配置门禁阻止")
finally:
    if original_model is None:
        os.environ.pop("LLM_MODEL", None)
    else:
        os.environ["LLM_MODEL"] = original_model
```

### Cell 5：验证配置与对象解耦

- 依赖：Cell 2；

## 4. WildAgent 对照提示

WildAgent 的 `create_llm(model_cfg=None, enable_thinking=False, streaming=False)` 同样返回由调用方持有的模型对象；配置默认来自全局 `config.chat`，也允许传入显式 `ModelConfig`。

## 5. 常见错误

| 现象 | 优先检查 |
|---|---|
| 创建对象后没有任何回答 | 只创建了 Client，还没有 `invoke()` |
| 聊天请求打到腾讯 Embedding | 把 `EMBEDDING_BASE_URL` 传给了聊天工厂 |
| 修改 `.env` 后对象仍用旧值 | Kernel 未重启或配置对象已提前创建 |
| 同一次请求重试很多次 | SDK重试与外层业务重试叠加 |
