# 第3章：消息与非流式调用

## 本章目标

使用 `invoke()` 和 Notebook 顶层 `await llm.ainvoke()` 完成真实调用，并读懂返回的 `AIMessage`。

## 前置知识

- 已完成第2章并保留 `chat_settings`、`normal_llm`；
- 当前聊天模型支持基础 Chat Completions；
- 明白这一章会产生真实模型请求和少量费用。

## 1. 消息不是普通字符串列表

聊天模型接收一串带角色的消息：

```text
SystemMessage：规定身份、任务和边界
HumanMessage：用户输入
AIMessage：历史模型回答或本次完整回答
```

LangChain 允许使用消息对象，也允许使用简写元组。学习阶段建议先使用显式消息对象，看清类型。

## 2. `AIMessage` 中有什么

| 字段 | 常见内容 |
|---|---|
| `content` | 自然语言字符串，也可能是内容块列表 |
| `additional_kwargs` | 供应商扩展字段，如 `reasoning_content` |
| `response_metadata` | 模型名、finish reason、供应商 Usage 等 |
| `usage_metadata` | LangChain归一化后的输入/输出/总 Token |
| `id` | 本次运行或消息标识 |

只打印 `response.content` 会隐藏大量诊断信息。

## 3. Notebook 分单元格练习

建立 `# 第3章：消息与非流式调用`。

### Cell 1：创建显式消息

- 依赖：第2章 Cell 3；
- 是否联网：否；
- 预期：看见两个不同消息类型。

```python
from langchain_core.messages import HumanMessage, SystemMessage

messages = [
    SystemMessage(
        content="你是Python学习助手。只回答当前问题，答案不超过三句话。"
    ),
    HumanMessage(
        content="ChatOpenAI对象和一次模型调用有什么区别？"
    ),
]

for message in messages:
    print(type(message).__name__, "=>", message.content)
```

### Cell 2：执行同步非流式调用

- 依赖：Cell 1、`normal_llm`；
- 是否联网：是；
- 输入：完整消息列表；
- 预期：等待完整回答后一次得到 `AIMessage`。

```python
response = normal_llm.invoke(messages)

print("返回类型：", type(response).__name__)
print("正文：", response.content)
```

如果这里失败，先看异常发生在连接、HTTP状态还是响应解析，不要立即修改 Prompt。

### Cell 3：检查完整响应结构

- 依赖：Cell 2；
- 是否联网：否；
- 预期：能区分正文、扩展字段、响应元数据和Usage。

```python
print("content类型：", type(response.content).__name__)
print("additional_kwargs：", response.additional_kwargs)
print("response_metadata：", response.response_metadata)
print("usage_metadata：", response.usage_metadata)
print("message id：", response.id)
```

记录你当前供应商把 `finish_reason` 和 Token Usage 放在哪个字段中。

### Cell 4：执行异步非流式调用

- 依赖：Cell 1、`normal_llm`；
- 是否联网：是；
- 预期：`await` 完成后仍得到一个完整 `AIMessage`。

```python
async_response = await normal_llm.ainvoke(messages)

print("异步返回类型：", type(async_response).__name__)
print("异步正文：", async_response.content)
```

Notebook 支持顶层 `await`，这里不要使用 `asyncio.run()`。

### Cell 5：比较同步与异步结果形态

- 依赖：Cell 2、Cell 4；
- 是否联网：否；
- 预期：两者类型和主要字段一致，调用等待方式不同。

```python
comparison = {
    "sync_type": type(response).__name__,
    "async_type": type(async_response).__name__,
    "sync_has_content": bool(response.content),
    "async_has_content": bool(async_response.content),
}
print(comparison)
```

不要断言两次正文完全相同。即使 `temperature=0`，第三方服务也不一定保证逐字一致。

### Cell 6：主动触发消息输入错误

- 依赖：无；
- 是否联网：否；
- 主动错误：把不支持的对象当作消息；
- 预期：在序列化或调用前出现类型错误。

```python
try:
    HumanMessage(content=object())
except Exception as exc:
    print("预期消息类型错误：", type(exc).__name__)
    print(exc)
```

这个错误在本地消息校验阶段发生，不会发送网络请求。请把 `content` 改为字符串，再说明修复依据。

## 4. 重点观察

- `invoke()` 返回一个完整消息，不是字符串；
- `ainvoke()` 的优势是等待期间可让出事件循环，不代表它会逐字返回；
- `response.content` 只是响应的一部分；
- 供应商兼容接口可能把扩展字段放进 `additional_kwargs`。
