## 1. 非流式与流式的差别

```text
非流式：请求 → 等待 → AIMessage

流式：请求 → Chunk1 → Chunk2 → Chunk3 → ... → 完整结果
```

流式不会自动给你最终字符串。调用方必须消费每个 Chunk，并决定如何向前端推送和如何保存完整结果。

## 2. 为什么启用 `stream_usage`

流式协议通常在最后一个 Chunk 才携带 Usage，而且有些兼容供应商不返回。`ChatOpenAI(stream_usage=True)` 会请求并尽量保留流式 Token 统计，但代码仍要允许 Usage 为空。

### Cell 1：同步消费流式 Chunk

- 依赖：第3章 Cell 1、`streaming_llm`；
- 是否联网：是；
- 输入：同一组消息；
- 预期：多次打印 `AIMessageChunk`，终端逐步出现正文。

```python
sync_chunks = []

for index, chunk in enumerate(streaming_llm.stream(messages), start=1):
    sync_chunks.append(chunk)
    print(
        f"chunk={index}",
        "type=", type(chunk).__name__,
        "content=", repr(chunk.content),
    )

print("Chunk数量：", len(sync_chunks))
```

某些 Chunk 的 `content` 可能为空，因为它只携带结束原因或 Usage。

### Cell 2：拼接同步流式正文

- 依赖：Cell 1；
- 是否联网：否；
- 预期：还原完整自然语言回答。

```python
sync_content = "".join(
    chunk.content
    for chunk in sync_chunks
    if isinstance(chunk.content, str)
)

print("拼接后的正文：")
print(sync_content)
```

这一写法只处理字符串正文。第5章会补充内容块列表的兼容处理。

### Cell 3：查找结束原因和Usage

- 依赖：Cell 1；
- 是否联网：否；
- 预期：找到最后出现的 finish reason；Usage可能存在，也可能为空。

```python
finish_reason = None
stream_usage = None

for chunk in sync_chunks:
    metadata = chunk.response_metadata or {}
    finish_reason = (
        metadata.get("finish_reason")
        or metadata.get("stop_reason")
        or finish_reason
    )
    if chunk.usage_metadata:
        stream_usage = chunk.usage_metadata

print("finish_reason：", finish_reason)
print("stream_usage：", stream_usage)
```

### Cell 4：异步消费流式 Chunk

- 依赖：第3章 Cell 1、`streaming_llm`；
- 是否联网：是；
- 预期：通过 `async for` 逐块显示，并拼出完整正文。

```python
async_content_parts = []
async_chunk_count = 0

async for chunk in streaming_llm.astream(messages):
    async_chunk_count += 1
    if isinstance(chunk.content, str) and chunk.content:
        async_content_parts.append(chunk.content)
        print(chunk.content, end="", flush=True)

async_content = "".join(async_content_parts)

print("\n异步Chunk数量：", async_chunk_count)
print("异步完整正文长度：", len(async_content))
```

Notebook 中直接使用顶层 `async for`，不要套 `asyncio.run()`。

### Cell 5：测量首块等待和总耗时

- 依赖：第3章的 `messages`、`streaming_llm`；
- 是否联网：是；
- 预期：得到首块耗时与总耗时，理解流式改善的是首屏体验。

```python
import time

started = time.perf_counter()
first_chunk_seconds = None
timed_parts = []

for chunk in streaming_llm.stream(messages):
    if first_chunk_seconds is None:
        first_chunk_seconds = time.perf_counter() - started
    if isinstance(chunk.content, str):
        timed_parts.append(chunk.content)

total_seconds = time.perf_counter() - started

print("首块等待：", round(first_chunk_seconds or 0, 3), "秒")
print("总耗时：", round(total_seconds, 3), "秒")
print("正文长度：", len("".join(timed_parts)))
```

### Cell 6：主动制造“只保留最后一块”的错误

- 依赖：Cell 1；
- 是否联网：否；
- 预期：`last_only` 通常只是空串、标点或最后一小段。

```python
last_only = sync_chunks[-1].content

print("错误做法得到：", repr(last_only))
print("正确完整正文：", repr(sync_content))
print("二者是否相同：", last_only == sync_content)
```

修复原则：在流式循环中累积所有正文块，不能用最后一个 Chunk 覆盖之前内容。

## 4. reasoning流与正文流

一些第三方供应商把推理增量放在：

```python
chunk.additional_kwargs.get("reasoning_content")
```

它不是所有 OpenAI-compatible 服务都支持的标准字段。读取时使用 `.get()` 并接受空值，不要假设一定存在。第5章会统一处理。
