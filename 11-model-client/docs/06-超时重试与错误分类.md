## 1. 三层容易混淆的控制

| 层 | 典型参数 | 作用 |
|---|---|---|
| HTTP/SDK | `timeout`、`max_retries` | 控制底层连接、读取和SDK自动重试 |
| Invocation Layer | `asyncio.wait_for()`、业务退避 | 控制整次调用上限和可观测重试 |
| Agent/Graph | 节点重试、修复循环 | 重做业务步骤，不应该处理鉴权或额度错误 |

三层都无限重试会放大延迟和费用。学习实现先把 SDK重试设为0，再清楚观察外层重试。

## 2. 哪些错误适合重试

| 错误 | 是否重试 | 原因 |
|---|---|---|
| 429限流 | 是，有限退避 | 稍后可能恢复 |
| 5xx服务异常 | 是，有限退避 | 供应商可能暂时不可用 |
| 连接或读取超时 | 是，有限退避 | 网络可能短暂抖动 |
| 401鉴权失败 | 否 | 重复同一Key不会恢复 |
| 403无权限 | 否 | 需要修改账号或权限 |
| 404模型不存在 | 否 | 需要修正模型或地址 |
| 400参数错误 | 否 | 原请求不改变就会继续失败 |
| 额度耗尽 | 否 | 必须充值或更换服务 |

### Cell 2：编写最小错误分类器

- 依赖：Cell 1；
- 是否联网：否；
- 输入：异常；
- 输出：稳定的类别与是否可重试。

```python
def classify_model_error(exc: Exception) -> dict:
    message = str(exc).lower()
    status_code = getattr(exc, "status_code", None)

    if status_code == 401 or "invalid api key" in message:
        return {"category": "authentication", "retryable": False}
    if status_code == 403:
        return {"category": "access_denied", "retryable": False}
    if status_code == 404 or "model not found" in message:
        return {"category": "model_not_found", "retryable": False}
    if status_code == 429 or "rate limit" in message or "too many requests" in message:
        return {"category": "rate_limited", "retryable": True}
    if isinstance(status_code, int) and status_code >= 500:
        return {"category": "provider_unavailable", "retryable": True}
    if isinstance(exc, TimeoutError) or "timeout" in message or "timed out" in message:
        return {"category": "transport_error", "retryable": True}
    if status_code == 400:
        return {"category": "invalid_request", "retryable": False}
    return {"category": "model_error", "retryable": False}


print(classify_model_error(rate_limit_error))
print(classify_model_error(auth_error))
```

### Cell 3：定义按脚本返回结果的假异步模型

- 依赖：Cell 1；
- 是否联网：否；
- 预期：每次调用依次取出异常或结果，并记录调用次数。

```python
class ScriptedAsyncModel:
    def __init__(self, outcomes):
        self.outcomes = list(outcomes)
        self.call_count = 0

    async def ainvoke(self, messages):
        self.call_count += 1
        outcome = self.outcomes.pop(0)
        if isinstance(outcome, Exception):
            raise outcome
        return outcome
```

### Cell 4：实现有限外层重试

- 依赖：Cell 2、Cell 3；
- 是否联网：否；
- 预期：最多尝试 `max_retries + 1` 次。

```python
import asyncio


async def invoke_with_retry(
    model,
    messages,
    *,
    timeout_seconds: float = 2.0,
    max_retries: int = 2,
):
    for attempt in range(max_retries + 1):
        try:
            return await asyncio.wait_for(
                model.ainvoke(messages),
                timeout=timeout_seconds,
            )
        except Exception as exc:
            error_info = classify_model_error(exc)
            print(
                "attempt=", attempt + 1,
                "category=", error_info["category"],
                "retryable=", error_info["retryable"],
            )

            if not error_info["retryable"] or attempt >= max_retries:
                raise

            delay = min(0.1 * (2 ** attempt), 1.0)
            await asyncio.sleep(delay)
```

学习代码使用很短的退避时间，方便 Notebook 观察；生产系统通常会使用更长退避并加入抖动。

### Cell 7：验证真正超时

- 依赖：Cell 4；
- 是否联网：否；
- 预期：等待超过上限后出现 `TimeoutError`，并按瞬态错误策略有限重试。

```python
class SlowAsyncModel:
    def __init__(self):
        self.call_count = 0

    async def ainvoke(self, messages):
        self.call_count += 1
        await asyncio.sleep(0.2)
        return "来得太晚的结果"


slow_model = SlowAsyncModel()

try:
    await invoke_with_retry(
        slow_model,
        [("human", "测试超时")],
        timeout_seconds=0.05,
        max_retries=1,
    )
except TimeoutError as exc:
    print("预期超时：", type(exc).__name__)

print("调用次数：", slow_model.call_count)
assert slow_model.call_count == 2
```

如果你的 Python 环境把异常显示为 `asyncio.TimeoutError`，它与内置 `TimeoutError` 在当前版本中是同一类超时语义。

## 4. 排错顺序

```text
是否收到HTTP响应？
→ 状态码是什么？
→ 是否属于瞬态错误？
→ 当前SDK已经重试几次？
→ 外层还会重试几次？
→ 本轮是否应该终止？
```

连接超时发生在收到 HTTP 响应之前；400/401/429/500则说明供应商已经返回响应。两者不能混为“模型坏了”。

如果在 `import asyncio` 阶段就出现 Windows `WinError 10106`，说明代码尚未进入模型调用，也没有收到供应商 HTTP 响应。这属于本机 Socket 服务初始化阻塞，应单独记录为运行环境问题，不能拿它证明模型、Key、Base URL 或重试策略有错。
