# 05：300 条模拟记忆导入与手动验证

这批数据完全虚构。它用于检查“从 300 条已形成的记忆中检索、筛选、回答、强化”，没有经过语言模型的记忆提取流程，因此不能用来验证 Appraisal 的提取质量。

## 1. 先导入，再启动对话

在 PowerShell 中执行下面两条命令。先等待导入完成，再启动 05，不要同时运行两个脚本。

```powershell
& "E:\AgentProject\studyAgent\.venv\Scripts\python.exe" "E:\AgentProject\studyAgent\12-memory\05.import_memories.py"
& "E:\AgentProject\studyAgent\.venv\Scripts\python.exe" "E:\AgentProject\studyAgent\12-memory\05.chroma.py"
```

导入脚本自动读取同目录的 `05.memories.json`，从项目根目录 `.env` 读取向量模型配置。无需修改 05，不需要先启动 Chroma 服务。

| 项目 | 使用内容 |
| --- | --- |
| 数据库路径 | `E:\AgentProject\studyAgent\12-memory\storge\chromadb` |
| 集合名称 | `hybrid_memory_05`，与 05 相同 |
| 必需配置 | `EMBEDDING_MODEL`、`EMBEDDING_API_KEY` |
| 可选配置 | `EMBEDDING_BASE_URL` |
| 向量化范围 | 只向量化每条记忆的 `content` |
| 导入批量 | 每批 10 条；不调用语言模型 |
| 重复导入 | 按固定 ID 跳过已有记录，不覆盖时间、正文和回忆强化 |
| 对话所需配置 | 启动 05 还需要原来的 `LLM_MODEL`、`LLM_API_KEY` 等配置 |

脚本同时向 Chroma 提交 ID、正文、真实向量和元数据，使用显式向量，避免额外调用默认嵌入模型。[Chroma 数据写入说明](https://docs.trychroma.com/docs/collections/add-data)

导入完成时，脚本会显示新增、跳过和集合总数。JSON 恰好有 300 条，ID 为 `demo_001` 到 `demo_300`。如果你已经用 05 聊过天，集合总数可能大于 300，原来的记录会保留。

## 2. 数据是什么样的

正文覆盖借书、书店、饮食、生日、朋友、通勤、旅行、工作、设备、宠物等内容。它包括：

- 相似干扰：不同图书馆、不同借书、不同人物、不同约定时间。
- 明确条件：邀请未确认、遇雨取消、加班改期、缺货登记等。
- 纠正关系：旧饮品偏好、旧地址、记错的生日、改期的陶艺课等。
- 年龄差异：刚形成的记忆到很久未提起的记忆。
- 历史强化：部分记录预置了历史回忆，数值按 05 的强化公式推导；这些是模拟历史，不是已经运行过的真实对话。
- 时间对照：最后 6 条故意使用完全相同的正文，只改变形成时间。

JSON 使用相对时间，首次导入该条记录时才换算成 UTC 时间：

| JSON 字段 | 含义 |
| --- | --- |
| `created_days_ago` | 多少天前形成，例如 7 表示一周前 |
| `last_recalled_days_ago` | 多少天前成功回忆；null 表示从未回忆 |
| `initial_strength` | 刚形成时的强度 |
| `strength_after_recall` | 最近一次回忆后的基准强度；没有回忆时等于初始强度 |
| `stability_days` | 衰减时间尺度，沿用 05 的含义 |
| `recall_count` | 预置的历史成功回忆次数 |
| `status` | 普通状态在导入时重算；superseded 保持已被修正 |
| `supersedes_id` | 当前记忆明确纠正了哪条旧记忆 |

不向量化相对时间、状态、预期答案或本提示词文档。回答模型只会收到 05 读取门槛允许的正文。

## 4. 单独检查时间是否参与排序

重启 05，保证短期窗口为空。选择 1，粘贴下面这一整句：

> 我和用户约定，“青苔暗号”表示每周三晚上八点给窗台绿植浇水。

这次只看检索表，不用 AI 最终回答评价事实回忆——因为输入本身已经包含答案。

`demo_295` 到 `demo_300` 的正文完全相同，初始强度都为 0.8，稳定性都为 72.2 天，从未回忆；唯一变化是形成时间。首次完整导入时，理论值约为：

| ID | 形成于多少天前 | 当前强度 | 初始状态 |
| --- | --- | --- | --- |
| demo_295 | 0 | 0.8000 | active |
| demo_296 | 7 | 0.7261 | active |
| demo_297 | 30 | 0.5280 | fading |
| demo_298 | 90 | 0.2300 | fading |
| demo_299 | 180 | 0.0661 | forgotten |
| demo_300 | 365 | 0.0051 | forgotten |

观察方法：

1. 进入候选表的这些记录，其语义相似度应基本一致。
2. 它们的综合分应随当前强度降低，年轻记录排在年老记录之前。只比较实际进入候选表的控制组记录；其他记忆也会竞争位置，不要求前 5 条全部来自控制组。
3. 若相似度一致而综合分完全相同，检查强度是否真正参与了评分。
4. `forgotten` 不等于禁止读取：当相似度达到 05 的强线索门槛 0.65 时，旧记忆仍可进入上下文。这符合当前实现。
5. 单纯成为候选不会增加次数；这条消息本身已包含内容，模型也可能只按当前输入回答，不应把所有相同正文的候选都强化。

这 6 条是有意设置的重复正文，专门隔离时间因素；不能把它们当成 6 个不同事实来计算事实覆盖率。

## 5. 检查遗忘与强线索

先重启 05，再选择对话，尝试：

> 很久以前我说过学骑自行车的那件小事，你还记得当时在哪里吗？

再补充不包含答案的线索：

> 我说的是青苔巷尽头的老邮局。邮局门前挂着什么，会被风吹响？

目标是 `demo_291`：老邮局、银色风铃。它形成于 540 天前，没有历史回忆，初始强度只有 0.45。

观察的是两次线索下，目标是否进入候选、相似度是否提高、是否允许读取。若第二问相似度达到 0.65，允许唤起 forgotten 记忆；若未达到，则仍可能想不起来。不要为了得到“银色风铃”而直接把这个答案输入给模型。

这不能保证第一问一定忘、第二问一定想起；相似度由你的真实向量模型决定。模型拿不到正文时，应自然表示不确定，不能凭“邮局”猜测门口装饰。

## 6. 检查强化与时间推进

**先验证一次实际回忆。** 重启 05，提问：

> 那次市图书馆邀请里，我让你带的、夹着蓝色便签的书叫什么？

如果 `demo_002` 获准读取且实际用于正确回答，05 应输出“成功回忆”，该记录回忆次数增加 1，上次回忆时间更新，稳定性和基准强度按原公式更新。只有候选命中，不应增加次数。

**紧接着检查短期窗口。** 接着问：

> 我们刚才说的是哪本书？

此时最近原话里已经有答案，按当前设计可直接 answered，不应仅因为长期候选也含同一事实就再次强化全部候选。具体采用情况要结合回答和使用 ID 核对。

**再验证时间。** 主菜单选择 2，输入：

```text
90
```

已有记忆的创建时间、上次回忆时间统一前移 90 天，短期窗口清空。对照前后总览中的强度和状态；这一步本身不应增加回忆次数，也不应调用向量模型。

随后可分别尝试：

> 青槐桥那次躲雨，借给我红伞的值班员叫什么？

> 山毛榉观景台旁边，我提过摆着什么东西？

292 和 293 都形成于 365 天前、初始强度都是 0.9。292 模拟了三次历史回忆，上次是 2 天前；293 没有回忆。可以直接比较两条的稳定性、上次回忆时间和当前强度。第二题的事实答案是“铜色小望远镜”，但它可能因强度低、线索不足而无法读取。若强线索相似度达标仍想起，也符合当前门槛规则。

注意：时间推进和回忆强化都会保存到数据库。重复导入默认跳过已有 ID，不恢复初始状态；重启也只清空短期窗口。因此连续操作是同一条实验历史，不能当作多次独立基线实验。

## 7. 怎样判断这次筛选有效

先看每轮 AI 回复上方的小表，而不是下方打印出来的全部长期记忆：

| 观察点 | 要确认的事情 |
| --- | --- |
| 候选是否正确 | 目标 ID 是否在综合评分前 5 条，是否被相似事件挤掉 |
| 读取是否正确 | “允许读取”一列是否与相似度、当前强度及门槛相符 |
| 答案是否正确 | 人物、书名、时间、条件与上表标注一致，不把邀请写成已确认 |
| 旧信息是否排除 | superseded 旧记录不进入候选，即便旧记录初始强度很高 |
| 强化是否正确 | 只对合法且真正用于回答的长期记忆计数，不对全部候选计数 |
| 无依据时是否克制 | 密码、北极旅行、已完成归还等不能被编造或擅自承认 |
| 重启是否持久 | 重启 05 后还能找到原记录，已发生的强化与时间变化仍保留 |

05 目前每轮最多展示 5 条评分候选，获准长期上下文也不超过 5 条；下方“长期记忆总览”打印 300 条只是调试输出，不等于 300 条都被交给大模型。

如果答错，先定位阶段：目标没进前 5，是检索或重排问题；进了前 5 但不允许读取，是门槛问题；允许读取且事实清楚却答错，是回答阶段问题。模型自报“成功回忆”和次数增加，只证明它登记了使用，仍需对照答案核实。

这份材料提供人工可核对的预期结果，没有预先运行真实模型来证明这些题已经通过。向量相似度门槛与衰减参数仍属于当前实验设置。
