# Linux + Docker：手机访问记忆实验室

适用于已安装 Docker 和 Docker Compose 插件的 Linux 服务器，暂时只有公网 IP。
默认端口 **80**，不加访问密码，使用一个 Python 进程管理三个版本。
手机访问同一个服务提供的页面和 API，不通过 IDE 的 `localhost:63342`。

## 1. 上传项目文件

把 `studyAgent` 上传到服务器，例如 `/opt/studyAgent`。可用你已有的 SFTP 工具，或提交代码后在服务器拉取。
上传时至少包含：

```text
/opt/studyAgent/
  .dockerignore
  pyproject.toml
  uv.lock
  README.md
  .env
  12-memory/contrast/
    web.py
    web_service.py
    static/
    v1/ v2/ v3/
    deploy/Dockerfile
    deploy/compose.yaml
```

不用上传 Windows 的 `.venv`、`.git`、300 条记忆 JSON 或其他学习目录。
`.env` 不在 Git 里，需要在服务器单独创建或通过 SFTP 上传；不要把它提交到仓库。

## 2. 配置服务器上的 .env

在 `/opt/studyAgent/.env` 中填写你的真实模型配置：

```dotenv
LLM_MODEL=你的文字模型名称
LLM_BASE_URL=你的文字模型接口地址
LLM_API_KEY=你的文字模型Key
EMBEDDING_MODEL=你的向量模型名称
EMBEDDING_BASE_URL=你的向量模型接口地址
EMBEDDING_API_KEY=你的向量模型Key
WEB_PORT=80
```

服务器须能访问这些模型接口。接口地址若指向你电脑的 localhost，迁到服务器后需要改成服务器实际可访问的地址。
Compose 在运行时注入 `.env`，Docker 镜像不包含模型密钥。

## 3. 构建并在后台启动

在服务器执行：

```bash
cd /opt/studyAgent
mkdir -p 12-memory/contrast/storge/web
docker compose --env-file .env -f 12-memory/contrast/deploy/compose.yaml up -d --build
docker compose --env-file .env -f 12-memory/contrast/deploy/compose.yaml logs -f --tail=100
```

第一次构建需要下载自带 Python 3.12 和 uv 的官方 GHCR 镜像及项目依赖，按根目录 `pyproject.toml` 与 `uv.lock` 安装。
不需要在服务器宿主机额外安装 Python 或 uv，也不用再分别启动三个版本。
`up -d` 后服务在后台运行，`logs -f` 只是查看日志；退出日志查看不会停止容器。
容器设置了 `restart: unless-stopped`，Docker 服务可用时会按该策略恢复运行。参见 [Compose 服务配置](https://docs.docker.com/reference/compose-file/services/)。

### 如果遇到 USTC 镜像域名无法解析

报错包含 `docker.mirrors.ustc.edu.cn` 和 `no such host` 时，失败的是 Docker Hub 镜像源解析。
[USTC 官方说明](https://mirrors.ustc.edu.cn/help/dockerhub.html)已标明镜像缓存服务关闭。

本项目 Dockerfile 已改为从 GHCR 直接拉取包含 Python 与 uv 的官方镜像，开头应只有这一行 `FROM`，不再单独拉取 Docker Hub 的 Python 镜像：

```dockerfile
FROM ghcr.io/astral-sh/uv:0.13.7-python3.12-trixie-slim
```

这个标签可在 [uv 官方镜像列表](https://github.com/astral-sh/uv/pkgs/container/uv)查看。
把更新后的 Dockerfile 同步到服务器，再重新执行上面的 `up -d --build`。
该方案绕过这次失效的 Docker Hub 镜像源，不需要为本项目重启整个 Docker 服务。
后续拉取其他 Docker Hub 镜像仍可能受旧镜像源配置影响，应另行维护服务器的 `registry-mirrors`；不要覆盖 `/etc/docker/daemon.json` 中其他已有配置。

## 4. 放行端口并用手机打开

在云服务器控制台的安全组/防火墙放行 **TCP 80 入站**。
如果 Linux 自己启用了防火墙，也允许该端口。不要关闭整个防火墙。

手机浏览器输入：

```text
http://你的服务器公网IP
```

不输入 `localhost`、`127.0.0.1` 或 `0.0.0.0`；这些地址不能代替手机要连接的服务器公网 IP。
默认不弹登录窗口，不需要访问密码。
页面顶部“记忆关联图”打开同一服务器上的 `/static/graph.html`。

当前是未加密 HTTP，而且按你的要求没有访问控制。知道地址的人可以调用聊天、读取和清空这些实验数据；此方式用于临时实验，长期使用再加 HTTPS 或改用私有网络。

## 5. 数据保存、更新和停止

容器里的 `12-memory/contrast/storge/web` 挂载到服务器项目的同名目录。
三版的 Chroma 数据、聊天日志、时间状态和共同实验时刻都在这里；重建镜像不会主动清空这些数据。
默认服务器从空记忆开始，不会导入那 300 条 JSON。手机与电脑打开同一服务器地址，看到的是同一套实验数据，不是不同用户的独立账号。

更新代码或修改 `.env` 后：

```bash
cd /opt/studyAgent
docker compose --env-file .env -f 12-memory/contrast/deploy/compose.yaml up -d --build --force-recreate
```

更新或停止前，等网页显示所有当前请求均已结束，再执行：

```bash
docker compose --env-file .env -f 12-memory/contrast/deploy/compose.yaml stop
```

Compose 还预留了 15 分钟正常退出时间，供正在进行的同步请求结束；强制结束进程可能中断当前写入。
不要删除 `storge/web`，除非你就是要清空全部 Web 数据。
同一份目录只运行一个服务实例；进程内的短期原话和操作锁不支持多副本共享。

## 手机页面与关联图

- 手机以标签切换 v1、v2、v3 的回答；顶部“对话对象”仍决定消息发给哪几版。
- 聊天下方保留记忆列表、详细字段、原始对话、关联维护记录和全部原始 JSON。
- 关联图支持单版或三版对比，手机默认先看一版，避免三张图挤在同一行。
- 图里保留全部记忆节点；只在勾选“只看选中节点及直接关联”时缩小展示范围，不改变数据库。
- `filling` 画为来源/证据箭头，`links` 画为语义关联虚线，`supersedes_id` 画为纠正箭头。边来自真实字段，没有根据向量相似度临时造边。
- 点击节点或下方完整列表可以查看详情，也能逐条查看全部入边、出边与对方正文。
- 图每 3 秒刷新，只读，不触发强化、关联构建或大模型调用；新关系在正常聊天的同步记忆处理期间落库。v2 使用纯 A-Mem 笔记及有向 links，没有强度或 thought。
