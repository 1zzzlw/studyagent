# 应用编排层

本目录协调四系统，业务计算留在各系统内部。初版已合并实现在 [runtime.py](runtime.py)，以下细分文件名保留为规划参考。

当前入口已改为 [reply_control](reply_control/README.md)：即时收消息，防抖聚合后由 Planner 判断，`Runtime.process_pending` 执行一批输入。下面的 handle_message 伪代码与同步顺序是早期设计参考，实际以本目录 Python 文件为准。

## 规划文件

| 文件 | 负责什么 |
| --- | --- |
| `bootstrap.py` | 初始化角色配置、仓库、模型与四个系统服务，传入依赖 |
| `conversation_flow.py` | `ConversationFlow.handle_message`：按顺序完成一次交流 |
| `time_flow.py` | `TimeFlow.advance`：将统一时间交给状态、情感和记忆系统 |

根目录已有 `main.py` 启动入口，运行方式见 [说明](../../README.md)。

## 一次交流的建议顺序

1. **记录用户原话。** 分配真实消息 ID、观察 ID 和时间，在模型调用之前保存。
2. **取得人物状态与已有情绪。** 各系统按同一个 `now` 完成本轮需要的恢复或时间计算，取得快照。
3. **检索相关记忆。** 以用户消息和有限近期对话取候选；此时不强化全部候选。
4. **评价本次反应。** 情感系统结合角色自身设定、原有情绪、当前处境与相关经历，生成一次情感评价并更新当前情绪。
5. **取得注意力评价。** 人物状态系统根据本轮状态、情绪影响及观察，给出本次 `AttentionAppraisal`。状态变化须走显式接口。
6. **组织回忆视图。** 记忆系统计算候选的当前强度，生成本轮回忆内容与清晰程度；不覆盖原始正文。
7. **一次调用生成回复。** 对话系统接收最新快照、回忆视图和有限近期消息，生成 `DialogueReply`。
8. **保存角色实际回复。** 回复失败时不创建虚假的成功发言；此前已保存的用户消息继续保留。
9. **登记实际采用的记忆。** 检查 `used_memory_ids` 均来自本轮允许集合，再交给记忆系统强化。
10. **整理本次交流。** 从真实交流提炼新事件；把注意力、情感评价作为形成时输入，初始化保留状态。
11. **维护关联与反思。** 新事件维护关联；反思达到条件时最多执行一轮。新 thought 可参与关联，但不立刻递归触发下一轮反思。

这个顺序避免“记忆唤起情绪，情绪再唤起记忆”在一轮内无限循环。更复杂的多轮内部思考暂不引入。

## 输入与输出契约草图

~~~text
handle_message(
    character_id,
    conversation_id,
    user_text,
    now,
) -> DialogueReply
~~~

编排时使用几类明确的中间结果：

| 结果 | 所属系统 | 用途 |
| --- | --- | --- |
| `CharacterStateSnapshot` | 人物状态 | 本轮角色处境与精力 |
| `AttentionAppraisal` | 人物状态 | 观察 ID、实际留意程度、简短依据 |
| `EmotionSnapshot` | 情感 | 本轮角色自身的情绪 |
| `EmotionAppraisal` | 情感 | 观察 ID、本次反应与 emotional_impact |
| `RecallItem` | 记忆 | 本轮允许使用的记忆与清晰程度 |
| `DialogueReply` | 对话 | 正文与 used_memory_ids |

上述类型由其所属系统定义；不要再创建一个塞入所有可变字段的大型共享人物类。

## 初始化强度的边界

规划调用：

~~~text
memory.remember(
    observation,
    attention_score=attention_appraisal.attention,
    emotional_impact=emotion_appraisal.emotional_impact,
)
~~~

记忆形成过程自行评价内容重要性，再把临时输入交给保留引擎计算初始强度。`MemoryNode` 不因此永久拥有当前状态和当前情绪。

人物状态或情感系统也不直接写 `MemoryNode`。

## 时间推进的边界

统一使用带时区的时间，运行时由初始化入口提供时钟。

时间推进应调用各系统的显式时间接口。记忆强度可以在读取时计算；人物状态和情绪各自决定是否需要更新快照。不要在不同系统里各自移动一遍相同的记忆时间。

Sentimo 原版的按轮恢复与本项目的时间推进不是同一机制，恢复单位和参数在实现情感引擎时单独确定。

## 初版执行方式

先使用同步、可逐步观察的调用顺序。对话系统的一次回复请求与其余模型请求分别记录。

现已实现模型连接、回复调度线程、离线测试和持久化；不会导入示例聊天数据。
