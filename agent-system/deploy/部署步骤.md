# Linux 服务器部署：Docker Compose

当前镜像提供 Python 后端 API，Flutter 客户端连接服务器地址。服务器已经安装 Docker 时，直接按下面步骤操作。

## 1. 本机准备部署包

在 Windows PowerShell 的 studyAgent 根目录执行：

```powershell
cd E:\AgentProject\studyAgent
tar --exclude="agent-system/.env" --exclude="agent-system/storge" --exclude="agent-system/tests" --exclude="*/__pycache__" --exclude="*.pyc" -czf agent-system-linux.tar.gz pyproject.toml uv.lock README.md agent-system
```

得到 `agent-system-linux.tar.gz`，包含依赖清单、锁文件和四系统代码。无需上传 Windows 的 `.venv`、学习用 notebook 或参考项目。实际模型配置单独使用已有 `agent-system/.env`，不装进镜像。

如果使用文件上传工具，也可以只上传 `pyproject.toml`、`uv.lock`、根 `README.md` 和 `agent-system` 代码目录，保持原目录结构。

## 2. 上传到服务器

把命令中的 `服务器IP` 换成实际公网 IP：

```powershell
scp .\agent-system-linux.tar.gz root@服务器IP:/opt/
scp .\agent-system\.env root@服务器IP:/opt/agent-system.env
```

也可以用已有的 SFTP 工具上传这两个文件。`.env` 中模型和向量接口需要能从服务器访问。

## 3. 在服务器解压并放好配置

SSH 登录服务器后执行：

```bash
mkdir -p /opt/studyAgent
tar -xzf /opt/agent-system-linux.tar.gz -C /opt/studyAgent
mv /opt/agent-system.env /opt/studyAgent/agent-system/.env
cd /opt/studyAgent
mkdir -p agent-system/storge/sqllite agent-system/storge/chromadb
```

最终目录：

```text
/opt/studyAgent/
├── pyproject.toml
├── uv.lock
├── README.md
└── agent-system/
    ├── .env
    ├── main.py
    ├── init.sql
    ├── agent/
    ├── storge/
    │   ├── sqllite/
    │   └── chromadb/
    └── deploy/
        ├── Dockerfile
        ├── Dockerfile.dockerignore
        └── compose.yaml
```

默认以新的空数据目录启动。要带上已有聊天和记忆，先停止本机后端，再单独复制完整 `agent-system/storge` 到服务器同一位置；保留 SQLite、Chroma 及其关联文件的一致状态。部署包本身不带数据库。

## 4. 构建镜像并后台启动

在 `/opt/studyAgent` 执行：

```bash
docker compose version
docker compose -f agent-system/deploy/compose.yaml config --quiet
docker compose -f agent-system/deploy/compose.yaml up -d --build
```

首次构建会下载基础镜像与锁定的 Python 依赖。构建使用 uv 官方 Python 3.12 镜像，安装现有 `uv.lock`，服务器无需额外安装 Python。配置和数据库通过运行时注入/挂载保留在镜像外。参考 [uv Docker 文档](https://docs.astral.sh/uv/guides/integration/docker/)、[Docker bind mount 文档](https://docs.docker.com/engine/storage/bind-mounts/)。

此目录自带 `Dockerfile.dockerignore`，优先于 studyAgent 根 `.dockerignore`，避免原 contrast 构建规则排除 agent-system；见 [Docker 构建上下文说明](https://docs.docker.com/build/concepts/context/#filename-and-location)。不需要改旧项目的 Docker 文件。

## 5. 查看启动状态

```bash
docker compose -f agent-system/deploy/compose.yaml ps
docker compose -f agent-system/deploy/compose.yaml logs -f --tail=100
```

按 Ctrl+C 退出日志查看，容器继续运行。再检查接口：

```bash
curl http://127.0.0.1/api/health
```

成功时返回类似 `{"status":"ok","character_name":"小忆"}`。也可在浏览器打开 `http://服务器IP/docs` 查看 API。

云服务器安全组放行 TCP 80；主机开启防火墙时也放行这个端口。Flutter 右上角服务器设置填：

```text
http://服务器IP
```

端口映射为 `"80:8000"`，即服务器 80 → 容器内 Python 服务 8000。Python 启动端口、Dockerfile 的 EXPOSE 和健康检查均保持 8000；HTTP 默认使用 80，外部地址可省略端口号。本机直接运行 Python 时仍使用 8000。

若服务器的 80 已被占用，修改 compose.yaml 中映射的左边，例如 `"18000:8000"`；外部访问地址和安全组相应改为 18000。容器内部保持 8000。

已有容器只改端口映射后，在 `/opt/studyAgent` 执行 `docker compose -f agent-system/deploy/compose.yaml up -d` 即可重新创建容器，无需重新构建镜像。

## 6. 以后更新代码

先等正在进行的回复和记忆整理结束，再更新代码文件。在服务器的 `/opt/studyAgent` 重新执行：

```bash
docker compose -f agent-system/deploy/compose.yaml up -d --build
```

运行数据持续存放在服务器 `agent-system/storge`，更新代码时保留该目录和 `.env`。首次升级到北京时间版本时，应用会先在 sqllite 目录备份旧库，再转换时间表示。

修改 `.env` 后重新创建容器，确保新配置注入：

```bash
docker compose -f agent-system/deploy/compose.yaml up -d --force-recreate
```

停止服务：

```bash
docker compose -f agent-system/deploy/compose.yaml down
```

当前角色调度在单进程内运行，保持一个后端容器和一个 Uvicorn worker。应用自行按北京时间处理，不依赖服务器系统时区。
